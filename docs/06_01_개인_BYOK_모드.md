## 1. 문서 목적

이 문서는 FlowPulse 사용자가 자신의 한국투자증권 Open API 키를 직접 발급받아 사용하는 BYOK(Bring Your Own Key) 구조의 가능성, 제품 범위, 보안 요구사항, 계약상 남는 위험과 단계별 도입안을 정의한다.

BYOK는 중앙 서비스가 하나의 API 키로 모든 사용자에게 시장정보를 재배포하는 구조를 피할 수 있다는 장점이 있다. 그러나 사용자가 자신의 키를 사용한다는 사실만으로 상업적 이용·제3자 앱 사용·서버 보관·시장정보 표시 문제가 자동 해결되는 것은 아니다.

---

## 2. 핵심 결론

> 개인 BYOK 모드는 폐쇄형 MVP와 개인용 분석 도구의 현실적인 대안이지만, 공개 FlowPulse 서비스의 데이터 계약을 완전히 대체하는 해결책으로 확정할 수 없다.

위험이 가장 낮은 형태는 다음과 같다.

```text
사용자 본인 명의 한투 API
→ 사용자 기기 또는 사용자 전용 실행환경
→ 본인용 데이터 조회와 Flow 계산
→ 본인만 확인
```

위험이 커지는 형태는 다음과 같다.

```text
사용자 API 키
→ FlowPulse 중앙 서버 보관
→ 다수 사용자 데이터 수집·가공
→ 웹·앱·Feed에 재전송
```

---

## 3. 공식 자료에서 확인된 사항

한국투자증권 제휴 안내는 개인고객을 `개인 본인 자산으로 자기만의 전략을 통해 매매하고자 하는 고객`으로 설명하고, 일반 Open API 신청 경로를 안내한다.

고객 대상으로 Open API 서비스를 제공하려는 제휴 대상은 투자일임업·투자자문업 등 제도권 금융회사 중심으로 안내되며, 일반 핀테크사는 제휴 불가 예시로 명시되어 있다.

또한 제휴기관이 KRX 시세정보를 앱에 표시하려면 KRX 또는 해외거래소와 정보이용계약이 필요하다고 안내한다.

따라서 다음을 구분해야 한다.

- 개인이 자기 자산과 전략을 위해 API를 사용하는 것
- 제3자 서비스가 사용자의 키를 받아 대신 호출하는 것
- 다수 사용자에게 시세와 가공 결과를 제공하는 것

공식 공개자료만으로 FlowPulse BYOK 방식 전체가 허용된다고 확정할 수 없다.

---

## 4. BYOK가 줄일 수 있는 위험

- FlowPulse 공용 키로 전체 사용자를 서비스하지 않음
- 사용자별 호출 한도와 인증이 분리됨
- 사용자가 자신의 계정으로 API를 신청함
- 사용자 본인에게만 데이터를 표시할 수 있음
- 중앙 서버의 원본 시장정보 재배포를 줄일 수 있음
- 개인 전용 분석도구로 제품 범위를 제한할 수 있음

BYOK는 `공용 데이터 공급 서비스`보다 `사용자 소유 분석도구`에 가까운 구조를 만들 수 있다.

---

## 5. BYOK로도 해결되지 않는 문제

- 제3자 앱에 App Key·Secret을 입력해도 되는가
- FlowPulse가 키를 서버에 보관해도 되는가
- FlowPulse 서버가 사용자 대신 API를 호출해도 되는가
- 사용자별 데이터를 중앙 서버에 장기 저장해도 되는가
- 유료 앱에서 한투 데이터를 이용해도 되는가
- Flow 지표와 AI 해설이 허용되는 가공인가
- 사용자에게 실시간 시세를 화면으로 다시 전달해도 되는가
- Feed·공유 카드에 당시 가격과 수급을 첨부해도 되는가
- 여러 사용자의 데이터를 합쳐 시장 전체 신호를 계산해도 되는가

모두 한국투자증권 및 필요한 경우 KRX·코스콤의 서면 확인이 필요하다.

## 6. 아키텍처 선택지

### A. 완전 로컬 BYOK

```text
한투 API ↔ 사용자 기기
             ├─ Flow 지표 계산
             ├─ 로컬 알림
             └─ 로컬 기록
```

#### 장점

- FlowPulse 서버가 키와 원본 데이터를 보관하지 않음
- 사용자별 데이터 격리 수준이 높음
- 중앙 재배포 위험을 가장 크게 줄임

#### 단점

- 모바일 백그라운드 제한
- 브라우저 CORS·네트워크 제한 가능성
- 기기 종료 시 수집 중단
- 장기 백테스트와 사후검증 데이터 부족
- Secret의 안전한 기기 저장 필요

#### 판단

개인용 초기 버전에 가장 안전한 후보지만 실제 API 호출 구조와 약관 확인이 필요하다.

### B. 사용자 전용 개인 수집 서버

```text
한투 API ↔ 사용자별 격리 수집기
                 ├─ 사용자 전용 DB
                 ├─ Flow 계산
                 └─ 사용자 앱
```

#### 장점

- 노트북·휴대전화 종료와 무관한 상시 수집
- 사용자별 데이터와 키 분리
- 장기 사후검증 가능

#### 단점

- FlowPulse가 인프라를 운영하면 제3자 보관·대리 호출 문제 발생 가능
- 사용자 수만큼 비용과 운영 복잡도 증가
- 키 유출과 금융정보 보호 책임 증가

#### 판단

기술적으로 FlowPulse에 가장 적합하지만 서면 허용 없이는 공개 서비스에 적용하지 않는다.

### C. 중앙 BYOK 프록시

```text
사용자 키 → FlowPulse 중앙 서버 → 한투 API
```

#### 장점

- 개발과 운영이 단순
- 통합 알림과 분석이 쉬움

#### 단점

- 다수 사용자의 Key·Secret 중앙 보관
- 원본 데이터 중앙 수집
- 제3자 서비스·재배포 성격 강화
- 침해사고 영향 범위 확대

#### 판단

정식 승인과 강한 보안체계 없이는 권장하지 않는다.

### D. 정식 제휴·시장정보 계약

FlowPulse 또는 제휴사가 정식 계약으로 데이터를 받아 사용자에게 제공한다.

#### 판단

공개 서비스의 최종 형태로 가장 명확하지만 자격·비용·승인 문제가 있다. 한국투자 공식 안내상 일반 핀테크사는 제휴 대상이 아닌 것으로 표시되어 있으므로 사업자 자격과 파트너 구조를 별도 검토해야 한다.

## 7. 권장 단계별 구조

### 1단계: 개발자 개인 BYOK

- 사용자: 개발자 본인 1인
- 키: 개발자 본인 명의
- 데이터: 본인만 확인
- 저장: 폐쇄형 서버
- 공유: 금지
- 목적: 데이터 필드·갱신주기·지표 계산 검증

### 2단계: 완전 로컬 개인용 BYOK 실험

- 사용자별 직접 API 발급
- 키는 사용자 기기에 보관
- 원본 데이터와 Flow 지표는 본인만 확인
- 중앙 Feed에 원본 수치 첨부 금지
- 서비스 제공 전에 한투 서면 확인

### 3단계: 제한 베타

- 사용자 전용 격리 저장소 검토
- 키 보관 방식과 대리 호출 서면 승인
- 데이터 보관기간과 가공 범위 확정
- 테스트 사용자 약관과 동의

### 4단계: 공개 서비스

- 정식 시장정보 계약 또는 허용된 데이터벤더
- 상용·재배포·가공 권한
- 중앙형 Flow 홈과 Feed 활성화

## 8. BYOK 모드 제품 범위

### 제공 가능 후보

- 사용자 본인용 현재가·차트
- 사용자 본인용 프로그램 수급
- Flow Shift·Sync·Confidence
- Program Dip Reversal·Rally Exit
- 본인 관심 종목 알림
- 본인 매매 기록과 사후검증

### 제한 또는 별도 확인

- 시장 전체 후보 랭킹
- 다른 사용자에게 실시간 신호 공유
- Feed의 가격·수급 스냅샷
- 여러 사용자의 지표 집계
- 유료 Playbook 제공
- B2B API

## 9. 온보딩 흐름

```text
BYOK 모드 설명
→ 한투 계좌·Open API 신청 안내
→ 사용자 본인이 App Key·Secret 발급
→ 저장 위치와 위험 고지
→ 연결 테스트
→ 데이터 항목·지연 상태 확인
→ 관심 종목 선택
→ 수집 및 Flow 계산 시작
```

FlowPulse가 한투 ID·비밀번호·보안카드·OTP를 요구해서는 안 된다.

## 10. 키 저장 원칙

### 우선순위

1. 사용자 기기의 OS 보안 저장소
2. 사용자별 격리된 Secret 저장소
3. 중앙 서버 암호화 저장은 최후 선택

### 필수 보안

- App Key·Secret 평문 저장 금지
- 로그·분석 이벤트·오류 메시지 노출 금지
- 클라이언트 화면에서 Secret 재표시 제한
- 전송 구간 TLS
- 키별 접근제어
- 주기적 회전과 폐기
- 백업에 Secret 포함 여부 관리
- 관리자도 원문 Secret을 볼 수 없게 설계

### 금지

- Git 저장소 커밋
- 브라우저 LocalStorage 평문 저장
- 앱 번들에 포함
- 고객센터 채팅·이메일로 키 전달 요청
- 여러 사용자 간 키 공유

## 11. 개인정보·금융정보 최소화

MVP에서는 다음 정보를 수집하지 않는 것을 기본으로 한다.

- 계좌 비밀번호
- 주문 비밀번호
- 공동인증서
- 보안카드·OTP
- 불필요한 잔고와 자산정보

시세·수급 분석만 필요하다면 주문·계좌 API 권한을 요청하지 않는다. 최소권한 원칙을 적용한다.

---

## 12. 자동주문과 분리

BYOK 연결이 되어도 MVP에서 다음은 제공하지 않는다.

- 자동주문
- AI 자동매매
- 사용자 대신 주문
- 백그라운드 무인매매

사용자는 증권사 앱에서 직접 주문하고 FlowPulse에는 판단과 결과만 기록한다.

---

## 13. 중앙 서버에 저장할 수 있는 정보 후보

계약 확인 전에는 원본 시장정보보다 사용자 설정 중심으로 제한한다.

- 관심 종목 코드
- 알림 설정
- 사용자가 직접 입력한 진입·청산 기록
- 지표 계산 버전
- 데이터 권리가 확인된 제한적 파생 상태
- 사용자 동의와 연결 상태

원본 가격·체결·수급·분봉 장기 저장은 별도 허용을 확인한다.

---

## 14. Feed와 공유 제한

BYOK 데이터는 사용자가 개인적으로 조회한 정보이므로 공개 Feed에 그대로 올릴 수 있다고 가정하지 않는다.

계약 확인 전 기본 정책:

- 원본 실시간 가격·수급 자동 첨부 금지
- 차트 스크린샷 자동 공유 제한
- 종목명과 사용자 의견 중심
- 지연된 공식 공개 데이터로 대체 가능한지 검토
- 사용자의 수동 입력과 공급사 원본 데이터를 구분

---

## 15. 장애와 키 만료

### 상태

- CONNECTED
- TOKEN_EXPIRED
- KEY_INVALID
- RATE_LIMITED
- PERMISSION_DENIED
- PROVIDER_DOWN
- USER_DISCONNECTED

### 제품 동작

- 마지막 정상 갱신 시각 표시
- 신규 신호 중단
- Flow Confidence 제한
- 키 재입력보다 토큰 갱신 우선
- 연속 실패 시 자동 호출 중단
- 사용자가 연결을 즉시 해제하고 데이터 삭제 가능

---

## 16. 사용성 위험

- 한투 계좌가 없는 사용자는 이용 불가
- API 신청 과정이 복잡함
- App Key·Secret 개념이 어려움
- 토큰 갱신과 오류 해결 부담
- 사용자별 호출 제한
- 설정 실패로 초기 이탈 가능

BYOK는 대중형 제품보다 전문가·초기 검증 사용자에게 먼저 제공하는 것이 적합하다.

---

## 17. 비용 구조

BYOK가 데이터 계약비를 줄일 수 있어도 다음 비용은 남는다.

- 사용자별 격리 인프라
- Secret 관리
- 장중 수집 서버
- 데이터베이스
- 알림
- 장애 모니터링
- 보안감사와 사고 대응
- 사용자 설정 지원

`API가 무료이므로 서비스 운영도 무료`라고 가정하지 않는다.

## 18. 한투 서면 문의안

```text
개인 고객이 본인 명의로 발급받은 한국투자 Open API App Key와 Secret을
제3자 개발 애플리케이션인 FlowPulse에 직접 연결하고, 사용자 본인만을 위해
국내주식 시세·프로그램매매·투자자 수급 데이터를 조회하여
수급 방향 전환, 동조, 신뢰도 등 자체 지표로 가공·표시하는 구조를 검토하고 있습니다.

1. 사용자의 기기에서 직접 API를 호출하는 방식이 허용되는지
2. 사용자별 격리 서버에서 키를 암호화 보관하고 대신 호출할 수 있는지
3. 원본 데이터와 분봉을 사용자 본인용으로 저장할 수 있는지
4. 자체 지표와 AI 설명으로 가공할 수 있는지
5. 유료 소프트웨어에서 사용할 수 있는지
6. Feed·공유 기능 없이 사용자 본인에게만 표시하면 재배포에 해당하는지
7. 필요한 별도 신청·제휴·거래소 계약이 무엇인지

서면으로 확인을 요청드립니다.
```

## 19. 출시 게이트

### 개인 내부 MVP

- 개발자 본인 키
- 본인만 접근

## 20. 출시 차단 조건

- 제3자 앱에서 개인 키 사용 허용 여부 미확인
- 중앙 서버의 키 보관·대리 호출 허용 여부 미확인
- 원본 데이터 저장·가공 권한 미확인
- 키가 앱·웹·로그에 평문 노출
- 사용자별 데이터 격리 실패
- 사용자가 연결과 데이터 삭제를 통제할 수 없음
- FlowPulse가 주문 비밀번호나 OTP를 요구
- 공개 Feed로 원본 데이터를 무단 공유

## 23. BYOK 선언

> FlowPulse BYOK 모드는 사용자의 키를 데이터 계약 회피 수단으로 이용하는 구조가 아니다. 사용자가 자신의 데이터 연결과 보안을 통제하는 개인용 분석 환경으로 설계하고, 허용 범위가 확인된 기능만 제공한다.
