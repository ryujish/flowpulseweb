## 1. 문서 목적

이 문서는 FlowPulse AI가 시장·종목·수급·Playbook 신호를 설명할 때 사용하는 입력, 출력 구조, 근거 규칙, 불확실성 표현, 금지사항, 오류 처리와 검증 기준을 정의한다.

AI의 역할은 매수·매도 결정을 대신하는 것이 아니라 다음을 돕는 것이다.

- 중요한 변화를 빠르게 이해
- 원본 데이터와 근거 확인
- 반대 근거 확인
- 다음 확인 조건 파악
- 해석의 무효 조건 파악
- 신호 결과와 설명의 사후검증

---

## 2. 최상위 정책

> AI는 데이터보다 앞서 말하지 않으며, 데이터가 말할 수 있는 범위를 넘어 결론을 만들지 않는다.

AI 해설은 항상 다음 순서를 따른다.

```text
변화 → 근거 → 이례성 → 반대 근거 → 확인 조건 → 무효 조건 → 신뢰도
```

---

## 3. AI의 역할

### 허용 역할

- 시장 수급 상태 요약
- 투자 주체별 Flow Shift 설명
- Flow Sync와 방향 충돌 설명
- Flow Confidence 구성 설명
- 가격과 수급의 Divergence 설명
- Program Dip Reversal 후보 이유 설명
- Program Rally Exit 발생 이유 설명
- 데이터 부족·지연·추정 상태 설명
- 과거 동일 버전 신호 결과 요약
- 사용자 기록의 규칙 준수 여부 정리

### 허용하지 않는 역할

- 확정적 종목 추천
- 사용자 대신 매수·매도 판단
- 목표가·예상수익 보장
- 자동주문 또는 주문 실행
- 손실 회복을 위한 추가 진입 유도
- 사용자 위험한도를 무시한 행동 제안
- 데이터가 없는 미래 가격 예측
- 법적·세무적 판단의 확정적 제공

## 4. 원본 데이터·계산·해석 분리

AI 해설 화면과 저장 구조에서 다음을 분리한다.

### 원본 데이터

- 현재가·등락률
- 거래량·거래대금
- 투자 주체별 누적 순매수
- 최근 5분·15분 변화량
- 데이터 기준 시각·출처·상태

### 계산 결과

- Flow Shift
- Flow Sync
- Flow Confidence
- Flow Divergence
- Flow Persistence
- Flow Acceleration
- Signal Phase
- Risk/Invalidation

### AI 해석

- 변화의 의미
- 근거 요약
- 반대 근거
- 확인 조건
- 무효 조건
- 한계와 불확실성

AI가 계산 결과를 임의로 다시 계산하거나 원본 수치를 변경하지 않는다.

## 5. AI 입력 데이터 원칙

### 허용된 입력만 사용

AI는 서버가 검증한 구조화 데이터만 입력받는다.

```text
market_snapshot
stock_snapshot
actor_flows
flow_metrics
playbook_state
price_confirmations
counter_evidence
invalidation_conditions
data_quality
historical_validation
user_record_summary
```

### 입력에 없는 사실

입력에 없는 수치·뉴스·공시·시장 원인을 추정해 사실처럼 말하지 않는다.

예시:

- 입력에 환율이 없으면 `환율 영향`을 원인으로 단정하지 않음
- 입력에 뉴스가 없으면 `뉴스로 인해 상승`이라고 말하지 않음
- 입력에 기관 세부유형이 없으면 연기금·금융투자로 세분화하지 않음

## 7. 표준 출력 스키마

AI는 자유형 문장만 반환하지 않고 구조화된 출력과 사용자 문장을 함께 반환한다.

```json
{
  "status": "AVAILABLE",
  "headline": "가격은 과매도 구간이지만 프로그램 매수 흐름은 유지되고 있습니다.",
  "summary": "가격 반전 조건은 아직 모두 충족되지 않았습니다.",
  "evidence": [],
  "counter_evidence": [],
  "confirmation_conditions": [],
  "invalidation_conditions": [],
  "confidence_explanation": "데이터 품질은 양호하지만 가격 확인이 미완료입니다.",
  "data_limitations": [],
  "source_timestamp": "2026-08-10T10:24:15+09:00",
  "reason_codes": [],
  "model_version": "...",
  "prompt_version": "..."
}
```

구조화 필드 검증에 실패하면 사용자 화면에 해설을 표시하지 않는다.

## 8. 필수 해설 순서

### 1. 한 문장 상태

현재 확인된 변화와 아직 확인되지 않은 부분을 함께 전달한다.

좋은 예:

> 가격은 과매도 구간이지만 프로그램 매수 흐름은 유지되고 있으며, 가격 반전은 아직 확인 대기 상태입니다.

나쁜 예:

> 프로그램이 사고 있으니 곧 반등합니다.

### 2. 근거

- 원본 데이터 수치
- Flow 지표
- 가격 확인 상태

### 3. 반대 근거

- 다른 투자 주체의 반대 방향
- 거래량 미확인
- 가격 확인 미완료
- 데이터 추정·지연

### 4. 확인 조건

앞으로 해석이 강화되기 위해 필요한 조건이다.

### 5. 무효 조건

현재 가설이 깨지는 조건이다.

### 6. Confidence 설명

점수의 높고 낮은 이유를 설명한다.

---

## 9. 근거 생성 규칙

### 허용되는 근거

- 구조화 입력에 존재
- 기준 시각이 명확
- Reason Code로 추적 가능
- 데이터 품질 기준 충족

### 근거 우선순위

1. 현재 선택 주체의 최신 수급
2. 가격 확인 상태
3. Flow Shift·Persistence·Acceleration
4. 주체 간 Flow Sync
5. 과거 동일 버전 검증 결과
6. 뉴스·공시 등 보조 맥락

뉴스·공시는 수급 데이터보다 높은 우선순위의 원인으로 자동 승격하지 않는다.

### 근거 개수

- 핵심 근거 2~4개
- 상세 화면 최대 6개
- 같은 의미를 반복하지 않음

---

## 10. 반대 근거 생성 규칙

반대 근거는 선택사항이 아니라 모든 핵심 해설의 필수 항목이다.

### 후보

- 기관·외국인·프로그램의 반대 방향
- Flow Sync 방향 혼재
- 매수 가속도 둔화
- Persistence 부족
- 가격 반전 미확인
- 거래량 미확인
- 시장 전체 Bearish Sync
- 데이터 지연·추정
- 과거 표본 부족

### 반대 근거가 없는 경우

`반대 근거 없음`이라고 단정하지 않는다.

표현:

> 현재 입력 데이터에서 뚜렷한 반대 근거는 확인되지 않았지만, 데이터 범위 밖의 위험은 반영되지 않았습니다.

---

## 11. 확인 조건 정책

확인 조건은 새로운 매수 지시가 아니라 현재 해석을 강화하는 관찰 조건이다.

### Program Dip 후보

- 5분 Envelope 하단 재진입
- 직전 5분봉 고가 돌파
- 직전 저점 방어
- 프로그램 최근 5분 순매수 유지
- 거래량 회복

### Program Rally Exit 후보

- 프로그램 Bearish Shift 유지
- 최근 5분 순매도 지속
- 5분 Envelope 상단 재진입
- 직전 5분봉 저점 이탈
- VWAP 하향 이탈

AI가 입력에 정의되지 않은 확인 조건을 새로 만들지 않는다.

---

## 12. 무효 조건 정책

무효 조건은 해설의 끝이 아니라 상단 위험 요약에도 노출한다.

### 가격 무효

- 당일 저점 이탈
- 신호 기준 저점 이탈
- 사용자 최대 손실 도달

### 수급 무효

- 선택 주체 Bearish Shift
- 최근 5분·15분 순매도
- 강한 Bearish Sync

### 데이터 무효

- 허용 지연 초과
- 핵심 입력 누락
- 공급사 정정 진행

### 시간 무효

- 확인 대기시간 초과
- 최대 보유시간 초과
- 장 마감 전 청산 시각

Hard Invalidation이 발생하면 기존 긍정 해설을 유지하지 않고 `신호 무효` 상태로 갱신한다.

---

## 13. Flow Confidence 설명 정책

### 반드시 설명할 내용

- 상승 확률이 아님
- 데이터와 신호의 신뢰 수준
- 점수를 올린 요인
- 점수를 낮춘 요인

예시:

> Flow Confidence 78점은 상승 확률 78%를 뜻하지 않습니다. 프로그램 데이터의 최신성과 수급 지속성은 양호하지만 가격 반전과 거래량 확인이 미완료되어 점수가 제한되었습니다.

### 금지

- 성공 확률 78%
- 적중률 78%
- 78% 확률로 상승

과거 검증에서 확률 모델을 별도로 보정하더라도 Flow Confidence와 예상수익 확률을 같은 이름으로 표시하지 않는다.

---

## 14. 데이터 상태별 해설

### REALTIME

> 프로그램 데이터는 10:24:15 기준 실시간 값입니다.

### DELAYED

> 외국인 수급은 1분 지연 데이터로 현재 흐름과 차이가 있을 수 있습니다.

### ESTIMATED

> 외국인·기관 수급은 장중 추정값이며 장 마감 후 확정값과 달라질 수 있습니다.

### STALE

> 프로그램 데이터가 허용 지연시간을 초과하여 현재 신호를 확정할 수 없습니다.

### MISSING

> 핵심 수급 데이터가 누락되어 AI 해설을 제공할 수 없습니다.

### CORRECTED

> 공급사 정정값이 반영되어 당시 신호 결과가 다시 계산되었습니다.

## 15. 해설 제공 가능 상태

| 상태 | 동작 |
|---|---|
| AVAILABLE | 전체 해설 제공 |
| LIMITED | 제한사항과 함께 부분 해설 |
| DATA_STALE | 해설 중단, 마지막 정상 상태 표시 |
| DATA_MISSING | 해설 중단 |
| CONFLICTED | 데이터 충돌 설명, 결론 제한 |
| AI_UNAVAILABLE | 원본 데이터와 Flow 지표만 제공 |

데이터가 부족할 때 자연스러운 문장을 만들기 위해 빈칸을 추정하지 않는다.

## 16. 시장 브리핑 정책

### 입력

- 시장 지수 상태
- 외국인·기관·개인·프로그램 Flow Shift
- CoreSync
- 시장 Flow Confidence
- 대표 수급 급변 종목
- 데이터 상태

### 출력

1. 오늘 시장 한 문장
2. 주도 매수·매도 주체
3. 동조 또는 방향 충돌
4. 주의할 반대 근거
5. 데이터 기준 시각

### 예시

> 외국인 매도는 약해지고 프로그램 매수는 강화되고 있지만 기관은 아직 순매도여서 시장 전체 동조는 제한적입니다.

지수 방향만으로 투자 주체의 원인을 단정하지 않는다.

## 17. 종목 Flow 해설 정책

### 우선 설명

- 선택 투자 주체의 변화
- 다른 주체와의 관계
- 가격과 수급의 일치·괴리
- 지속성과 가속도
- 가격 확인 상태

### 예시

> 가격은 최근 5분간 하락했지만 프로그램 순매수는 증가해 양의 수급 괴리가 발생했습니다. 다만 기관 순매도가 지속되고 있어 프로그램 수급만으로 반전을 확정하기 어렵습니다.

## 18. Program Dip Reversal 해설 템플릿

```text
[상태]
{종목}은 가격 과매도 상태에서 프로그램 {매수상태}가 확인되었습니다.
현재 Signal Phase는 {phase}입니다.

[근거]
- 프로그램 누적 순매수 {cum}
- 최근 5분 프로그램 {flow5}
- 프로그램/거래대금 비율 {ratio}
- {price_confirmation}

[반대 근거]
- {counter_1}
- {counter_2}

[확인 조건]
- {confirmation_1}
- {confirmation_2}

[무효 조건]
- {invalidation_1}
- {invalidation_2}

[신뢰도]
Flow Confidence {confidence}/100. {confidence_reason}
```

템플릿 변수는 검증된 구조화 입력으로만 채운다.

---

## 19. Program Rally Exit 해설 템플릿

```text
[상태]
가격은 {profit_or_overbought_state}에 있으며 프로그램 매수는 {weakening_state}입니다.
현재 {exit_severity} 조건이 확인되었습니다.

[근거]
- 최근 5분 프로그램 {flow5}
- Flow Shift {shift}
- {price_reversal_confirmation}

[반대 근거]
- {counter_1}
- {counter_2}

[다음 확인]
- {exit_confirmation_1}

[위험·시간 조건]
- {hard_exit_1}
- 장 마감 전 당일청산 원칙

[신뢰도]
Flow Confidence {confidence}/100. {confidence_reason}
```

AI는 `매도하세요`가 아니라 `청산 조건 충족`, `수익 보호 조건`처럼 상태를 설명한다.

## 20. 분할진입 기록 해설

AI는 다음 차수 진입을 권하지 않는다. 현재 조건 충족과 규칙 이탈 여부를 설명한다.

### 허용

> 현재 프로그램 매수 흐름과 Flow Confidence는 유지되고 있지만 직전 5분봉 고가 돌파 조건은 아직 충족되지 않았습니다.

### 금지

> 지금 3차 매수하세요.

### 가격 하락 시

> 가격이 추가 하락했지만 수급 확인 조건이 약화되어 규칙상 다음 분할진입 조건은 충족되지 않았습니다.

---

## 21. 당일청산 해설

데이트레이딩 Playbook에는 다음 원칙을 항상 연결한다.

- 다음 날 보유하지 않음
- 장 마감 전 전량청산 기록
- 목표수익 미도달 시에도 시간청산

표현:

> 이 Playbook은 당일청산을 전제로 검증됩니다. 마감 전 지정 시각까지 잔여 수량이 있으면 시간청산 조건으로 분류됩니다.

오버나이트 전환을 대안으로 권하지 않는다.

## 22. 사후검증 해설 정책

### 입력

- 신호 발생가
- 10분·30분·종가 결과
- MFE·MAE
- Rally Exit 시각과 가격
- 사용자 진입·청산 기록
- 규칙 준수 여부
- 동일 버전 표본

### 출력

1. 신호 결과
2. 사용자 결과
3. 규칙 준수
4. 잘 작동한 조건
5. 실패 또는 약화 요인
6. 표본 한계

### 예시

> 신호 후 30분 최대 상승폭은 1.8%였지만 장중 최대 불리 변동폭도 -0.7%였습니다. 사용자는 가격 확인 후 진입하고 Program Rally Exit에서 일부 청산해 당일청산 원칙을 지켰습니다. 동일 버전 표본은 아직 18건으로 일반화하기에 부족합니다.

성과가 좋지 않은 경우에도 같은 구조로 설명한다.

## 23. 과거 성과 표현 정책

### 필수 표시

- 표본 수
- 신호 버전
- 시장 국면
- 거래비용·슬리피지 반영 여부
- 평균과 중앙값
- MFE·MAE

### 금지

- 적은 표본으로 `검증 완료`
- 승률만 단독 강조
- 실패 표본 제외
- 다른 버전 결과 무분별한 합산
- 과거 성과를 미래 수익 보장으로 표현

### 표현

> 과거 동일 버전 신호 42건에서 30분 중앙값은 +0.4%였습니다. 거래비용과 실제 체결 차이에 따라 결과가 달라질 수 있습니다.

숫자는 실제 검증 데이터가 있을 때만 사용한다.

- 원본 해설 보존
- 정정 사유
- 수정된 입력·지표·정책 버전
- 사후검증 영향

사용자 신고가 들어왔다고 AI 출력만 수정하고 원본 데이터 오류를 방치하지 않는다.

---

## 47. AI 완료 기준

1. 구조화 입력과 출력이 정의되어 있다.
2. 모든 숫자를 입력 데이터로 추적할 수 있다.
3. 근거·반대 근거·확인·무효 조건이 포함된다.
4. Confidence를 상승 확률로 표현하지 않는다.
5. 데이터 지연·추정·누락을 표시한다.
6. STALE·MISSING 상태에서 해설을 중단한다.
7. AI 장애 시 원본 데이터 기능이 유지된다.
8. 금지 표현 자동 검사가 존재한다.
9. 모델·프롬프트·정책·지표 버전을 저장한다.
10. 신호 결과와 당시 해설을 사후검증할 수 있다.

---

## 48. 출시 차단 조건

- 입력에 없는 숫자를 생성
- Confidence를 상승 확률로 표현
- 매수·매도 직접 지시
- 수익 보장 또는 목표가 단정
- 반대 근거·무효 조건 미제공
- 데이터 지연·누락 은폐
- STALE 데이터로 강한 신호 생성
- BYOK Secret이 AI 입력·로그에 포함
- 해설 버전과 입력 스냅샷 추적 불가
- AI 장애가 핵심 데이터 화면을 차단

---

## 49. 확정 정책

1. AI 해설은 근거 기반으로만 생성한다.
2. 반대 근거는 필수다.
3. 확인 조건과 무효 조건을 함께 제시한다.
4. Flow Confidence는 상승 확률이 아니다.
5. 데이터 부족 시 모른다고 표시하거나 해설을 중단한다.
6. 자동주문·매수·매도 지시를 제공하지 않는다.
7. 당일청산 Playbook에서 오버나이트를 권하지 않는다.
8. 원본 데이터·계산 결과·AI 해석을 분리한다.
9. 모든 해설은 기준 시각과 버전을 가진다.
10. AI 해설도 사후 결과와 함께 검증한다.
