## 1. 문서 목적

이 문서는 FlowPulse 사용자가 중요한 수급 변화를 발견하고, 근거와 위험을 확인하고, 자신의 판단과 기록을 남긴 뒤 실제 결과를 검증하는 전체 경험을 설계한다.

UX의 목표는 더 많은 거래를 유도하는 것이 아니라 다음을 가능하게 하는 것이다.

- 짧은 시간 안에 핵심 상태 파악
- 신호의 근거와 반대 근거 확인
- 가격 하락만으로 추가 진입하지 않도록 지원
- 익절·손절·시간청산 규칙 유지
- 데이터와 AI의 불확실성 이해
- 자신의 판단과 결과를 반복 검증

---

## 2. UX 비전

> 사용자가 하루 종일 차트를 보지 않아도 중요한 변화를 놓치지 않고, 앱이 시키는 대로가 아니라 자신의 규칙에 따라 판단할 수 있는 경험

### 핵심 UX 순환

```text
발견 → 이해 → 확인 → 판단 → 기록 → 검증 → 학습
```

각 단계는 앞 단계의 근거를 보존해야 하며 결과 검증에서 다시 확인할 수 있어야 한다.

---

## 3. 핵심 UX 원칙

1. 위험을 기회보다 먼저 보여준다.
2. 상태를 점수만으로 표현하지 않는다.
3. 가격과 수급을 같은 시간축에서 확인한다.
4. 근거와 반대 근거를 동시에 제공한다.
5. 확인 조건과 무효 조건을 행동 전에 보여준다.
6. 추가 진입은 가격 하락이 아니라 조건 확인으로 활성화한다.
7. 당일청산 Playbook은 마감 전에 반드시 종료 경로를 제공한다.
8. 데이터 지연·추정·누락을 숨기지 않는다.
9. AI가 결정권자로 보이지 않게 한다.
10. 결과가 좋지 않은 경험도 검증에서 제거하지 않는다.

## 4. 주요 UX 대상

### 직장인 사용자

- 확인 가능 시간: 출근 전, 점심시간, 짧은 휴식
- 요구: 짧은 요약과 중요한 변화 알림
- 위험: 알림만 보고 근거 없이 행동
- UX 대응: 알림에서 근거·반대 근거·무효 조건으로 바로 연결

### 수급 적극 사용자

- 확인 가능 시간: 장중 반복 확인
- 요구: 최근 5분·15분 변화와 차트
- 위험: 과도한 조건 조정과 과최적화
- UX 대응: 지표 버전·검증 결과·표본 수 제공

### 초보 수급 사용자

- 요구: 숫자의 의미와 상태 문구
- 위험: Confidence를 상승 확률로 오해
- UX 대응: 점수 옆에 설명과 제한 표시

### BYOK 사용자

- 요구: 본인 API로 개인 분석
- 위험: 키 보안과 복잡한 설정
- UX 대응: 단계별 연결, 최소권한, Secret 재표시 금지

## 5. UX 성공 조건

### 발견

- 사용자가 30초 안에 시장 방향과 중요 신호를 말할 수 있음

### 이해

- 사용자가 Flow Shift·Sync·Confidence의 차이를 설명할 수 있음

### 위험 인식

- 사용자가 행동 전에 반대 근거와 무효 조건을 확인함

### 기록

- 분할진입·청산 기록에 과도한 입력 부담이 없음

### 종료

- 당일청산 Playbook이 미종료 상태로 남지 않음

### 검증

- 사용자가 신호 결과와 자신의 결과를 구분해 이해함

## 6. 핵심 사용자 여정 1: 30초 시장 파악

### 시작 상황

사용자가 업무 중 잠시 FlowPulse를 연다.

### 목표

- 누가 사고 파는지 파악
- 시장 동조 여부 파악
- 확인할 후보 발견

### 여정

```text
Flow 홈 진입
→ 데이터 상태 확인
→ 오늘 시장 한 문장
→ 주체별 Shift
→ Flow Sync·Confidence
→ 중요 신호 카드
```

### UX 요구사항

- 첫 화면에서 스크롤 전 시장 한 문장과 CoreSync 확인
- 데이터 지연 시 요약보다 경고 우선
- `+41` 옆에 `약한 매수 동조` 병기
- 시장 문장 선택 시 근거 펼침

### 성공 기준

사용자가 30초 안에 다음을 답한다.

1. 주도 주체
2. 반대 주체
3. 전체 동조 방향
4. 데이터 신뢰 수준

---

## 7. 핵심 사용자 여정 2: Program Dip 후보 검토

### 시작

Program Dip 알림 또는 Flow 홈 후보 카드를 선택한다.

### 여정

```text
후보 카드
→ Signal Phase 확인
→ 원본 가격·프로그램 수급
→ Flow 지표
→ 근거·반대 근거
→ 가격 확인 조건
→ 무효 조건
→ 관찰 시작 여부 판단
```

### UX 핵심

- `후보`와 `진입 확인`을 다른 상태로 표현
- Envelope 하단 이탈만으로 완료처럼 보이지 않게 함
- 무효 조건을 카드 하단 고정 영역에 표시
- `관찰 시작`을 기본 행동으로 제공
- 직접 주문 CTA 없음

### 사용자가 이해해야 할 문장

> 프로그램 매수는 확인됐지만 가격 반전은 아직 확인 대기입니다.

---

## 8. 핵심 사용자 여정 3: 4~5회 조건부 분할진입

### UX 목표

분할진입을 단순 물타기가 아니라 조건 확인 과정으로 경험하게 한다.

### 여정

```text
관찰 시작
→ 최대 차수·위험 설정
→ 1차 기록
→ 다음 확인 조건 표시
→ 조건 충족 알림
→ 2~5차 기록
→ 조건 악화 시 추가 진입 중단
```

### 차수별 UX

| 차수 | UI가 우선 보여줄 것 |
|---|---|
| 1차 | 초기 가격 반전 징후와 위험 한도 |
| 2차 | Envelope 하단 재진입 |
| 3차 | 직전 5분봉 고가 돌파 |
| 4차 | 프로그램 매수 지속과 Confidence |
| 5차 | VWAP 또는 추가 가격 확인 |

조건은 백테스트 후 변경될 수 있으므로 UI는 고정 문구가 아니라 버전된 조건 목록을 렌더링한다.

### 추가 진입 중단 UX

```text
추가 진입 중단
프로그램이 최근 5분 순매도로 전환했습니다.
현재 Playbook의 다음 차수 조건은 충족되지 않습니다.
```

사용자가 계속 기록하려면 `규칙 이탈로 기록`을 명시적으로 선택한다.

---

## 9. 핵심 사용자 여정 4: Program Rally Exit

### 시작

보유 기록이 있는 종목에서 과매수와 프로그램 매수 약화가 발생한다.

### 여정

```text
Rally Exit 알림
→ 현재 수익률
→ 프로그램 Shift·Acceleration
→ 가격 반락 확인
→ Exit Severity
→ 부분·전량청산 기록
```

### UX 단계

- 수익 보호 준비
- 분할청산 조건
- 강한 청산 조건
- 전량청산 조건

### 중요한 구분

- 고정 1~3% 목표수익
- 프로그램 수급 기반 동적 익절
- 가격 손절
- 수급 손절
- 시간청산

청산 기록 시 사용자가 이유를 선택해 이후 검증에서 비교할 수 있게 한다.

---

## 10. 핵심 사용자 여정 5: 당일청산

### UX 목표

다음 날 보유하지 않는 Playbook 원칙을 사용자가 놓치지 않게 한다.

### 여정

```text
마감 전 사전 알림
→ 잔여 수량 확인
→ 청산 기록
→ 당일청산 완료
```

### 알림 단계

- 사전 준비
- 청산 시각 임박
- 미종료 경고

정확한 기본 시각은 실제 주문 가능시간과 사용자 테스트 후 확정한다.

### 예외

사용자가 다음 날까지 보유하면 숨기지 않고 `Playbook 규칙 이탈`로 기록한다.

---

## 11. 핵심 사용자 여정 6: 사후검증

### 여정

```text
거래 종료
→ 신호 결과
→ 사용자 결과
→ 규칙 준수
→ MFE·MAE
→ 동일 버전 비교
→ 다음 검증 항목
```

### UX 원칙

- 수익·손실 모두 같은 형식
- 승률보다 평균손익·MFE·MAE 함께 표시
- 사용자 결과와 신호 자체 결과 구분
- 실제 기록과 가상의 완벽한 진입을 혼동하지 않음

### 결과 설명

```text
신호는 30분 내 +1.8%까지 상승했지만 최대 불리 변동폭은 -0.7%였습니다.
사용자는 가격 확인 후 진입하고 당일청산 원칙을 지켰습니다.
```

## 12. 핵심 사용자 여정 7: BYOK 연결

### UX 목표

어려운 API 연결 과정을 안전하고 이해 가능한 단계로 만든다.

### 여정

```text
BYOK 설명
→ 지원 범위·제한 확인
→ 한투 API 발급 안내
→ 저장 방식 선택
→ App Key·Secret 입력
→ 연결 테스트
→ 지원 데이터 확인
→ 수집 시작
```

### 원칙

- 한 화면에 모든 설정을 요구하지 않음
- ID·비밀번호·OTP를 요구하지 않는다고 명시
- Secret 입력 후 원문 재표시 안 함
- 주문 권한 미사용을 확인
- 연결 해제와 삭제 경로 제공

### 성공

사용자가 자신의 데이터가 어디에 저장되는지 설명할 수 있어야 한다.

## 13. 정보 점진적 공개

### 1단계: 상태

```text
프로그램 매수 유지
Flow Sync +32 · 약한 매수 동조
Confidence 78 · 높음
```

### 2단계: 핵심 근거

- 누적 순매수
- 최근 5분 변화량
- 가격과 수급 괴리
- 무효 조건

### 3단계: 상세 계산

- 15분·누적 정규화
- 구성 점수
- Reason Code
- 지표 버전

초보 사용자는 1·2단계만으로 이해하고 전문 사용자는 3단계까지 확인할 수 있게 한다.

카드를 눌러야만 무효 조건을 알 수 있는 구조는 피한다.

## 15. Flow 지표 이해 지원

### Flow Shift

```text
매수 전환
최근 매도 우위에서 매수 우위로 바뀌었습니다.
```

### Flow Sync

```text
+32 · 약한 매수 동조
프로그램과 외국인은 매수 방향이지만 기관은 반대입니다.
```

### Flow Confidence

```text
78/100 · 높음
상승 확률이 아니라 데이터와 신호의 신뢰 수준입니다.
```

### Flow Divergence

```text
가격↓ / 프로그램↑
가격과 프로그램 수급이 반대로 움직입니다.
```

### Flow Persistence

```text
매수 흐름 18분 지속
최근 15개 구간 중 12개가 같은 방향입니다.
```

### Flow Acceleration

```text
매수 속도 증가
최근 5분 순매수가 직전 구간보다 증가했습니다.
```

---

## 16. Confidence 오해 방지 UX

### 점수 표시

```text
Flow Confidence 78/100
데이터·신호 신뢰도 높음
```

### 도움말

> 상승 확률이나 예상수익률이 아닙니다.

### 구성 보기

- 데이터 품질
- 유동성
- 지속성
- 시간축 일치
- 가격·거래량 확인
- 과거 표본

점수에 퍼센트 기호를 사용하지 않는다.

---

## 17. 근거와 반대 근거 UX

### 배치

근거를 먼저 표시하되 반대 근거를 접힌 탭이나 별도 페이지에 숨기지 않는다.

### 예시

```text
근거 3
✓ 프로그램 누적 순매수 증가
✓ 최근 5분 매수 속도 증가
✓ 가격과 수급의 양의 괴리

반대 근거 2
! 기관 순매도 지속
! 거래량 회복 미확인
```

근거 개수가 많다는 이유만으로 신호가 더 강하다고 표현하지 않는다.

---

## 18. 확인 조건 UX

확인 조건을 진행 체크리스트로 보여준다.

```text
가격 확인 2/4
[완료] 30분 Envelope 하단 이탈
[완료] 직전 저점 방어
[대기] 5분 Envelope 하단 재진입
[대기] 직전 5분봉 고가 돌파
```

`2/4`를 매수 준비율 또는 성공확률로 표현하지 않는다.

---

## 19. 무효 조건 UX

### 기본 노출

```text
무효 조건
당일 저점 이탈 또는 프로그램 최근 5분 순매도 전환
```

### Soft Warning

- 경고 아이콘
- Confidence 감점 이유
- 관찰 유지 가능

### Hard Invalidation

- 화면 상단 고정
- 추가 진입 중단
- 기존 긍정 해설 갱신
- 사용자 기록 경로 유지

무효 상태는 붉은색뿐 아니라 텍스트와 아이콘으로 표현한다.

---

## 20. 기록 UX 최소화

### 자동 제안 가능 항목

- 현재 시각
- 권한이 확인된 현재가
- 당시 신호 ID
- Flow 지표 스냅샷

### 사용자 입력

- 수량 또는 비중
- 실제 체결가 수정
- 이유 선택
- 선택 메모

### 원칙

- 20초 안에 한 차수 기록

## 21. 기록 실수 방지

- 평균 진입가와 시장가 혼동 방지
- 전량청산 후 추가 청산 차단
- 날짜가 바뀌면 당일청산 규칙 이탈 확인
- 중복 제출 방지

주문 앱과 FlowPulse 기록이 다를 수 있으므로 사용자가 수정할 수 있게 한다.

사용자가 화면 문구를 그대로 읽는 것보다 자신의 말로 설명할 수 있는지 본다.

## 49. UX 인수 기준

### 핵심 이해

- Signal Phase 구분
- Confidence 오해 없음
- 반대 근거와 무효 조건 발견

### 핵심 행동

- 관찰 시작
- 분할진입 기록
- 청산 기록
- 당일청산 완료
- 사후검증 조회

### 복구

- 데이터 지연 인지
- AI 장애에서도 데이터 확인
- BYOK 오류에서 안전한 재연결

중요 과제에서 반복적인 오해가 발생하면 시각 완성도와 관계없이 설계를 수정한다.

- 근거·반대 근거의 병렬·세로 배치

안전 관련 정보의 노출 여부는 A/B 테스트로 줄이지 않는다.

## 53. UX 완료 기준

1. 핵심 여정이 모바일에서 중단 없이 완료된다.
2. 사용자가 30초 안에 시장 상태를 파악한다.
3. 후보와 진입 확인을 구분한다.
4. 반대 근거와 무효 조건이 행동 전에 노출된다.
5. 4~5회 분할진입이 조건 확인 과정으로 표현된다.
6. Rally Exit와 당일청산 흐름이 연결된다.
7. 신호 결과와 사용자 결과가 구분된다.
8. 데이터 지연·추정·누락을 이해할 수 있다.
9. AI 장애 시 핵심 기능이 유지된다.
10. BYOK 연결·해제·삭제를 사용자가 통제한다.
11. 자동주문 또는 수익 보장으로 오해되는 문구가 없다.
12. 접근성 기본 조건을 충족한다.
