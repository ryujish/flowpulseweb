## 1. 문서 목적

이 문서는 FlowPulse MVP에서 반드시 구현할 기능과 후속 기능, 명시적으로 제외할 기능, 화면별 범위, 데이터 요구사항 및 완료 기준을 확정한다.

MVP의 목적은 많은 기능을 출시하는 것이 아니라 다음 핵심 가설을 처음부터 끝까지 검증하는 것이다.

> 사용자는 단순 누적 수급보다 수급의 방향 전환·동조·신뢰도와 가격 확인 조건을 함께 볼 때 더 빠르고 일관되게 상황을 판단할 수 있으며, 신호의 사후 결과가 축적되면 FlowPulse를 반복해서 사용할 이유가 생긴다.

---

## 2. MVP 한 문장 정의

> 프로그램·외국인·기관·개인의 수급 변화를 공통 Flow 엔진으로 분석하고, Program Dip Reversal과 Program Rally Exit를 대표 Playbook으로 제공하여 후보 발견부터 사용자 판단 기록, 당일청산, 사후검증까지 연결하는 모바일 우선 투자 인사이트 MVP

---

## 3. MVP 검증 목표

### 제품 가치 검증

- 사용자가 30초 안에 시장과 종목의 핵심 수급 상태를 파악하는가
- Flow Shift·Sync·Confidence가 기존 누적 수급보다 이해에 도움이 되는가
- 근거·반대 근거·확인·무효 조건이 신뢰 형성에 도움이 되는가
- 신호 결과와 사용자 기록이 재방문 이유가 되는가

### 대표 Playbook 검증

- 하락·과매도 종목의 프로그램 매수 유입이 반등 후보 탐색에 유효한가
- 누적 순매수에 최근 5분·15분 흐름을 추가하면 신호 품질이 개선되는가
- 최대 4~5회 조건부 분할진입 규칙이 단순 물타기와 구분되는가
- 고정 1~3% 익절과 Program Rally Exit의 결합이 유효한가
- 가격·수급·시간 손절과 당일청산 원칙이 실제로 지켜지는가

### 기술 검증

- 서버가 장중 데이터를 안정적으로 수집·저장하는가
- REST 초기 조회와 WebSocket 변경분 전달이 일관되게 작동하는가
- 모바일 웹과 Capacitor 앱에서 실시간 카드와 차트가 안정적으로 동작하는가
- 단절 후 재연결과 누락 데이터 복구가 가능한가

## 4. 범위 우선순위 정의

| 등급 | 의미 |
|---|---|
| P0 | MVP 출시와 핵심 가설 검증에 필수 |
| P1 | MVP 안정화 후 추가할 높은 우선순위 |
| P2 | 후속 확장 또는 유료 기능 후보 |
| 제외 | MVP에서 구현하지 않음 |

P0 기능 중 데이터 계약이나 API 제공 범위가 확인되지 않은 항목은 임의 데이터로 공개하지 않는다. 폐쇄형 검증, 테스트 데이터, 기능 플래그 중 하나로 구분한다.

---

## 5. MVP 핵심 순환

```text
실시간 데이터 수집
→ Flow 지표 계산
→ Program Playbook 후보 탐지
→ 핵심 신호 카드와 AI 해설
→ 사용자 판단·분할진입 기록
→ 수급 변화와 청산 조건 알림
→ 당일청산 기록
→ 사후 결과 자동검증
```

이 흐름이 실제 데이터 또는 명확히 구분된 검증 데이터로 끝까지 동작하지 않으면 MVP가 완료된 것으로 보지 않는다.

## 7. 공통 Actor 신호 엔진 범위

### P0 엔진 설계

다음 공통 구조를 투자 주체 파라미터로 계산할 수 있어야 한다.

```text
Actor Dip Reversal
과매도 + 선택 주체의 매수 유입·유지

Actor Rally Exit
과매수 + 선택 주체의 매수 둔화·매도 전환
```

지원 대상:

- 프로그램
- 외국인
- 기관
- 개인

### P0 공개 Playbook

- Program Dip Reversal
- Program Rally Exit

### 단계적 공개

외국인·기관·개인 Playbook은 공통 엔진에서 계산 가능하도록 구현하되 다음 조건을 충족한 주체부터 기능 플래그로 공개한다.

- 장중 데이터 제공 범위 확인
- 지연·추정 여부 확인
- 최소 표본 확보
- 주체별 임계값 백테스트
- Flow Confidence 보정

임계값 검증 없이 Program Playbook의 설정을 그대로 복사하지 않는다.

## 8. 핵심 지표 P0 범위

### 8.1 Flow Shift

필수 상태:

- Strong Bullish Shift
- Bullish Shift
- Weakening Sell
- Neutral
- Weakening Buy
- Bearish Shift
- Strong Bearish Shift

필수 지원:

- 매도에서 매수로 전환
- 매수에서 매도로 전환
- 전환 발생 시각
- 전환 후 유지시간
- 선택 투자 주체
- 지표 버전

### 8.2 Flow Sync

필수 상태:

- Bullish Sync
- Bearish Sync
- Divergent
- Neutral

기본 표현 범위는 `-100~+100`을 우선 사용하되 계산식과 구간은 `05_독자수급지표.md`에서 확정한다.

### 8.3 Flow Confidence

필수 평가 요소:

- 데이터 완전성
- 지연 및 갱신 상태
- 신호 지속성
- 시간축 일치도
- 가격 확인
- 거래량 확인
- 지표 간 일치
- 과거 표본 수

`78점 = 상승 확률 78%`로 오해되지 않도록 설명을 제공한다.

### 8.4 보조 핵심 지표

| 지표 | P0 역할 |
|---|---|
| Flow Divergence | 가격과 선택 주체의 반대 흐름 표시 |
| Flow Persistence | 현재 방향의 지속시간과 일관성 표시 |
| Flow Acceleration | 매수·매도 속도의 강화·약화 표시 |
| Risk/Invalidation | 무효 가격·수급·데이터 조건 표시 |
| Signal Phase | 후보부터 종료까지 현재 단계 표시 |

Flow Impact·Flow Strength·Flow Z-Score는 내부 계산 또는 P1 상세 지표로 둔다.

## 9. Program Dip Reversal P0 범위

### 후보 조건

- 당일 하락 종목
- 프로그램 누적 순매수 기준 충족
- 프로그램 순매수/거래대금 비율 기준 충족
- 30분 Envelope 하단 이탈
- 5분 Envelope 하단 이탈 또는 재진입
- 최근 5분·15분 프로그램 흐름 확인
- 최소 거래대금 및 유동성 기준
- 제외 종목 조건

고정 `프로그램 순매수 5억원`만 사용하지 않고 거래대금 대비 비율을 함께 검증한다.

### 신호 단계

1. 후보 탐색
2. 반전 확인 대기
3. 진입 조건 충족
4. 수급 유지
5. 매수 약화
6. 청산 조건 충족
7. 신호 무효
8. 종료

### 진입 확인 후보

- 5분 Envelope 하단 재진입
- 직전 5분봉 고가 돌파
- 직전 저점 또는 당일 저점 방어
- 거래량 회복
- VWAP 회복

정확한 조합과 임계값은 백테스트 후 확정한다.

## 10. 분할진입 기록 P0 범위

FlowPulse는 주문을 실행하지 않고 사용자의 직접 주문 결과를 기록한다.

### 필수 기록

- 최대 분할 횟수: 4회 또는 5회 선택
- 차수별 시각
- 차수별 가격
- 차수별 수량 또는 비중
- 평균 진입가
- 남은 진입 가능 횟수
- 당시 Flow 지표 스냅샷
- 진입 조건 충족 여부
- 규칙 이탈 여부

### 추가 진입 중단

- 선택 주체 Bearish Shift
- 최근 구간 순매도 전환
- 당일 저점 이탈
- Flow Confidence 기준 미달
- 데이터 지연·누락
- 사용자가 설정한 최대 손실

가격 하락만을 이유로 다음 진입 단계가 활성화되어서는 안 된다.

## 11. Program Rally Exit P0 범위

### 후보 조건

- 사용자의 기록상 보유 수량 존재
- 가격이 과매수 또는 목표수익 구간에 접근
- 프로그램 매수 가속도 둔화
- 최근 5분 프로그램 순매도 전환
- 프로그램 Bearish Shift
- Envelope 상단 재진입 또는 가격 반락 확인

### 청산 상태

- 수익 보호 준비
- 1차 분할청산 조건
- 추가 분할청산 조건
- 전량청산 조건
- 시간청산 조건

### 필수 원칙

- 고정 1~3% 목표수익과 동적 Rally Exit를 함께 검증
- 가격 손절·수급 손절·시간 손절 유지
- 장 마감 전 지정 시각 전량청산
- 다음 거래일까지 보유하지 않음

정확한 익절 비중과 손절률은 MVP 개발 전에 임의 확정하지 않고 검증 가능한 설정값으로 관리한다.

## 12. 핵심 신호 카드 P0 범위

모든 핵심 카드에는 다음 공통 지표를 표시한다.

1. Signal Phase
2. Flow Shift
3. Flow Sync
4. Flow Confidence
5. Flow Divergence
6. Flow Persistence
7. Flow Acceleration
8. Risk/Invalidation

신호별 원본 데이터:

- 현재 가격 상태
- 선택 주체 누적 순매수
- 최근 5분 순매수 변화량
- 거래대금 대비 수급 비율
- 신호 발생 시각
- 마지막 데이터 갱신 시각

### Program Dip Reversal 카드 예시

```text
Program Dip Reversal
반전 확인 대기 · 발생 10:24

현재가                       -2.4%
프로그램 누적 순매수           +8.2억원
최근 5분 프로그램 순매수        +1.1억원
프로그램/거래대금 비율           3.4%

Flow Shift                  프로그램 매수 유지
Flow Sync                   +32 · 약한 매수 동조
Flow Confidence             78/100 · 높음
Flow Divergence             가격↓ / 프로그램↑
Flow Persistence            매수 흐름 18분 지속
Flow Acceleration           매수 속도 증가

무효 조건
당일 저점 이탈 또는 프로그램 순매도 전환
```

### Program Rally Exit 카드 예시

```text
Program Rally Exit
수익 보호 조건 · 발생 13:42

현재 수익률                  +2.1%
최근 5분 프로그램 순매수        -0.8억원

Flow Shift                  프로그램 Bearish Shift
Flow Sync                   -21 · 방향 혼재
Flow Confidence             81/100
Flow Divergence             가격↑ / 프로그램↓
Flow Persistence            매도 흐름 7분 지속
Flow Acceleration           매도 속도 증가
```

## 16. AI 해설 P0 범위

## 31. MVP 성공 기준

정확한 목표 수치는 제한된 내부 검증 후 확정한다. 초기에는 다음 방향을 평가한다.

### 사용성

- 사용자가 30초 안에 핵심 수급 상태를 설명할 수 있음
- 핵심 신호 카드의 8개 공통 지표를 이해할 수 있음
- 신호 발생 시각을 차트에서 찾을 수 있음

### 신뢰성

- 원본 데이터·계산 결과·AI 해석이 구분됨
- 모든 핵심 신호에 기준 시각과 Confidence가 존재함
- 지연·누락 상태가 정상적으로 노출됨
- 실패 신호도 사후검증에 포함됨

### 완결성

- 후보부터 당일청산과 결과 검증까지 한 흐름으로 완료 가능
- 사용자 기록과 신호 데이터가 연결됨
- 자동주문 없이도 Playbook 검증 가능

## 32. 기능별 완료 정의

기능은 다음 조건을 모두 만족할 때 완료로 본다.

1. 사용자 시나리오가 처음부터 끝까지 동작한다.
2. 정상·로딩·빈 상태·오류·지연 상태가 구현된다.
3. 기준 시각과 데이터 출처를 추적할 수 있다.
4. 지표 계산 버전이 저장된다.
5. 근거·반대 근거·확인·무효 조건이 연결된다.
6. 사후검증 데이터가 자동 생성된다.
7. 모바일 웹과 Capacitor 앱에서 검증된다.
8. 접근성 기본 조건을 충족한다.
9. 분석 이벤트가 정의된다.
10. 자동주문 없이 사용자 직접 판단 원칙을 유지한다.

## 35. 확정 사항과 미확정 사항

### 확정

- Flow Shift·Sync·Confidence는 P0 필수
- Flow Shift는 양방향
- 공통 Actor 신호 엔진 적용
- Program Dip Reversal과 Program Rally Exit는 P0 대표 Playbook
- 최대 4~5회 조건부 분할진입 기록
- 고정 1~3% 익절과 동적 익절 동시 검증
