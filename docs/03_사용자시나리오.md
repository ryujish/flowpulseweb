## 1. 문서 목적

이 문서는 FlowPulse의 목표 사용자가 실제 상황에서 어떤 문제를 해결하기 위해 제품을 사용하고, 어떤 정보를 확인하며, 어떤 판단과 기록을 남기는지를 정의한다.

각 시나리오는 이후 `04_MVP_SCOPE.md`, 정보구조, 화면기획, 알림 정책, 데이터 설계 및 완료 기준의 근거가 된다.

FlowPulse의 기본 사용자 흐름은 다음과 같다.

```text
발견 → 이해 → 확인 → 판단 → 기록 → 검증
```

## 2. 핵심 사용자 유형

### 사용자 A: 짧은 시간에 확인하는 직장인 투자자

- 장중 시장을 계속 볼 수 없다.
- 출근 전·점심시간·짧은 휴식시간에 확인한다.
- 프로그램·외국인·기관 수급을 참고한다.
- 큰 수익보다 짧은 구간의 규칙적인 청산을 선호한다.
- 자동주문보다 조건과 위험을 확인한 후 직접 주문하기를 원한다.

### 사용자 B: 수급 중심 적극 투자자

- 장중 수급과 가격 변화를 자주 확인한다.
- 누적 순매수보다 최근 5분·15분 변화와 방향 전환을 중요하게 본다.
- 조건검색식과 차트를 함께 사용한다.
- 자신의 전략을 과거 데이터와 실제 결과로 검증하려 한다.

### 사용자 C: 수급 해석이 어려운 일반 투자자

- 외국인·기관·프로그램 수치는 확인하지만 의미를 판단하기 어렵다.
- 왜 신호가 발생했는지 쉬운 설명을 원한다.
- 긍정 근거뿐 아니라 반대 근거와 무효 조건도 필요하다.

### 사용자 D: 데이터 기반 의견 공유 사용자

- 특정 종목에 대한 관찰이나 매매 가설을 공유한다.
- 작성 당시 가격·수급·차트를 함께 남기고 싶다.
- 이후 실제 결과와 자신의 판단을 비교하고 싶다.

## 3. 공통 사용자 여정

| 단계 | 사용자 질문 | FlowPulse의 역할 |
|---|---|---|
| 발견 | 지금 중요한 변화가 무엇인가 | 수급 급변과 복합 신호 탐지 |
| 이해 | 왜 이 신호가 발생했는가 | 근거 기반 AI 해설 |
| 확인 | 반대 근거와 위험은 무엇인가 | 확인·무효 조건 및 Confidence 제공 |
| 판단 | 지금 관찰·진입·청산 중 무엇을 할 것인가 | 신호 단계를 명확히 표시 |
| 기록 | 나는 어떤 판단을 했는가 | 사용자 판단과 분할 내역 기록 |
| 검증 | 실제 결과는 어땠는가 | 사후 결과 자동 연결 |

## 4. 시나리오 1: 30초 안에 시장 수급 파악

### 사용자 상황

직장인이 장 시작 후 잠시 휴대전화를 확인한다. 시장 전체를 오래 볼 수 없으며 중요한 변화만 빠르게 알고 싶다.

### 사용자 목표

- 오늘 시장의 매수·매도 주체 확인
- 주요 Flow Shift 및 Flow Sync 확인
- 확인할 가치가 높은 종목 후보 발견

### 사용자 흐름

1. 사용자가 Flow 홈을 연다.
2. 오늘 시장 한 문장과 기준 시각을 확인한다.
3. 외국인·기관·개인·프로그램의 현재 방향을 확인한다.
4. 시장 전체 Flow Shift와 Flow Sync를 확인한다.
5. 수급 급변 종목과 대표 Playbook 후보를 확인한다.
6. 관심 있는 종목을 선택하거나 관심 종목에 저장한다.

### 제품 표시

```text
시장 Flow Shift       외국인 매도 약화 / 기관 매수 유지
시장 Flow Sync        +41 · 약한 매수 동조
Flow Confidence       82/100
마지막 갱신           10:22:15
```

### 예외 상황

- 일부 데이터 지연 시 해당 주체를 회색 상태로 표시한다.
- 전체 신뢰도가 낮으면 강한 시장 결론을 생성하지 않는다.

### 완료 조건

사용자가 30초 안에 시장 방향과 확인할 종목 하나 이상을 파악한다.

## 5. 시나리오 2: Program Dip Reversal 후보 발견

### 사용자 상황

하락 종목 중 프로그램 순매수가 들어오는 종목을 찾고 싶다. 가격 과매도와 프로그램 매수 흐름이 동시에 확인되는 후보만 보고 싶다.

### 진입 계기

- 사용자가 Playbook 목록을 연다.
- 또는 Program Dip Reversal 후보 알림을 받는다.

### 사용자 흐름

1. 후보 종목 카드를 확인한다.
2. 신호 발생 시각과 데이터 갱신 상태를 확인한다.
3. 가격 하락률과 Envelope 상태를 확인한다.
4. 프로그램 누적 순매수와 최근 5분·15분 변화량을 확인한다.
5. 핵심 신호 카드 지표를 확인한다.
6. 종목 상세로 이동하여 차트의 신호 발생 지점을 확인한다.

### 핵심 신호 카드

```text
Program Dip Reversal
반전 확인 대기 · 발생 10:24

현재가                       -2.4%
프로그램 누적 순매수           +8.2억원
최근 5분 프로그램 순매수        +1.1억원
프로그램/거래대금 비율           3.4%

Flow Shift                  프로그램 매수 유지
Flow Sync                   +32 · 약한 매수 동조
Flow Confidence             78/100 · 높음
Flow Divergence             가격↓ / 프로그램↑
Flow Persistence            매수 흐름 18분 지속
Flow Acceleration           매수 속도 증가

가격 확인
30분 Envelope               하단 이탈
5분 Envelope                하단 재진입 대기
직전 저점                    방어 중

무효 조건
당일 저점 이탈 또는 프로그램 순매도 전환
```

### 완료 조건

사용자가 단순 순매수 금액뿐 아니라 방향·동조·신뢰도·지속성·무효 조건을 확인한다.

## 6. 시나리오 3: 근거와 반대 근거 확인

### 사용자 목표

후보가 실제로 관찰할 가치가 있는지 판단한다.

### 사용자 흐름

1. 신호 카드의 `왜 발생했나요?`를 선택한다.
2. 원본 데이터와 AI 설명을 구분해 확인한다.
3. 근거와 반대 근거를 함께 읽는다.
4. 다음 확인 조건과 무효 조건을 확인한다.
5. 신호를 관찰 목록에 추가하거나 닫는다.

### 제품 표시 예시

```text
근거
- 가격 하락 중 프로그램 누적 순매수 증가
- 최근 5분 프로그램 매수 속도 증가
- 30분 Envelope 하단 이탈
- 직전 저점 방어 중

반대 근거
- 기관 현물 순매도 지속
- 거래량 회복 미확인
- 5분 Envelope 하단 재진입 미확인

확인 조건
- 5분 Envelope 하단 재진입
- 직전 5분봉 고가 돌파
- 프로그램 순매수 증가 유지

무효 조건
- 당일 저점 이탈
- 최근 5분 프로그램 순매도 전환
- Flow Confidence 기준 미달
```

### 예외 상황

AI 해설 생성에 실패해도 원본 데이터와 계산 결과는 정상 제공한다.

---

## 7. 시나리오 4: 첫 번째 진입 판단과 기록

### 사용자 상황

사용자가 실제 증권 앱에서 직접 주문한다. FlowPulse는 주문하지 않으며 사용자의 판단과 기록만 지원한다.

### 사용자 흐름

1. 5분 Envelope 하단 재진입 또는 가격 반전 조건을 확인한다.
2. 프로그램 매수 흐름과 Flow Confidence가 유지되는지 확인한다.
3. 사용자가 직접 1차 진입 여부를 판단한다.
4. 진입했다면 수량·가격·시각 또는 비중을 기록한다.
5. 사용자가 최대 진입 횟수와 위험 한도를 설정한다.

### 제품 피드백

```text
현재 단계            1차 진입 기록
남은 분할 횟수        4회
프로그램 상태         매수 유지
추가 진입 허용        확인 조건 대기
무효 조건까지 거리     -0.8%
```

### 안전 원칙

- `지금 매수` 같은 자동 지시를 제공하지 않는다.
- 목표 수익과 손실 한도를 사용자가 확인하도록 한다.
- 데이터가 지연되면 진입 기록 전에 경고한다.

---

## 8. 시나리오 5: 최대 4~5회 조건부 분할진입

### 사용자 목표

가격 하락만을 이유로 물타기하지 않고 수급과 가격 확인이 유지될 때만 나누어 진입한다.

### 분할진입 예시

| 차수 | 확인 조건 예시 | 사용자 행동 |
|---|---|---|
| 1차 | 하단 재진입 또는 반전 징후 | 최소 비중 진입 기록 |
| 2차 | 프로그램 매수 유지 | 추가 진입 여부 판단 |
| 3차 | 직전 5분봉 고가 돌파 | 확인 후 추가 진입 |
| 4차 | Flow Confidence 유지·상승 | 추가 진입 여부 판단 |
| 5차 | VWAP 회복 또는 강한 가격 확인 | 최종 추가 진입 판단 |

비중과 정확한 임계값은 사용자 설정과 백테스트 결과에 따라 결정하며 초기 단계에서 고정하지 않는다.

### 추가 진입 중단 조건

- 최근 5분 프로그램 순매도 전환
- 프로그램 Bearish Shift
- 당일 저점 이탈
- Flow Confidence 급락
- 거래량을 동반한 추가 급락
- 데이터 지연 또는 누락
- 최대 손실 도달

### 제품 피드백

조건이 깨지면 `추가 진입 중단` 상태를 카드 최상단에 표시하고 관련 알림을 발송한다.

## 9. 시나리오 6: 프로그램 매수 유지와 약화 확인

### 사용자 상황

사용자가 업무 중 계속 화면을 볼 수 없다. 프로그램 수급의 의미 있는 변화만 확인하고 싶다.

### 사용자 흐름

1. 사용자가 프로그램 상태 변화 알림을 받는다.
2. 알림에서 기준 시각과 핵심 변화량을 확인한다.
3. 앱을 열어 Flow Shift·Persistence·Acceleration을 확인한다.
4. 추가 진입·유지·청산 준비 중 어느 상태인지 확인한다.

### 알림 예시

```text
[프로그램 매수 유지]
최근 5분 +1.1억원, 매수 흐름 18분 지속
Flow Confidence 78
```

```text
[프로그램 매수 약화]
최근 5분 증가분이 +1.1억원에서 +0.2억원으로 감소
과매수 진입 시 수익 보호 조건을 확인하세요.
```

알림은 매수·매도 명령이 아니라 상태 변화를 전달한다.

## 10. 시나리오 7: Program Rally Exit에 따른 동적 익절

### 사용자 상황

보유 종목이 1~3% 수익 구간에 접근했고 가격은 과매수 상태다. 프로그램 매수세가 둔화하거나 매도로 전환되기 시작한다.

### 사용자 흐름

1. 과매수 및 프로그램 매수 약화 알림을 받는다.
2. Program Rally Exit 카드를 확인한다.
3. 현재 수익률과 프로그램 최근 5분 흐름을 확인한다.
4. Bearish Shift와 가격 반락 확인 여부를 확인한다.
5. 사용자가 직접 일부 또는 전량청산 여부를 판단한다.
6. 청산 수량·가격·시각을 기록한다.

### 핵심 신호 카드

```text
Program Rally Exit
수익 보호 조건 · 발생 13:42

현재 수익률                  +2.1%
프로그램 누적 순매수           +9.4억원
최근 5분 프로그램 순매수        -0.8억원

Flow Shift                  프로그램 Bearish Shift
Flow Sync                   -21 · 방향 혼재
Flow Confidence             81/100
Flow Divergence             가격↑ / 프로그램↓
Flow Persistence            매도 흐름 7분 지속
Flow Acceleration           매도 속도 증가

가격 확인
5분 Envelope                상단 재진입
직전 고점                    돌파 실패
```

### 청산 단계 예시

1. 고정 최소수익 구간에서 일부 수익 보호
2. 과매수와 매수 둔화가 함께 발생하면 추가 분할청산 검토
3. Bearish Shift가 확인되면 잔여 비중 축소 검토
4. 매도 지속과 가격 반락이 함께 확인되면 전량청산 검토

정확한 비중과 임계값은 검증 전까지 확정하지 않는다.

## 11. 시나리오 8: 손절 및 신호 무효 처리

### 사용자 상황

가격이 반등하지 않고 당일 저점을 이탈하거나 프로그램이 순매도로 전환한다.

### 사용자 흐름

1. 무효 조건 알림을 받는다.
2. 어떤 조건이 깨졌는지 확인한다.
3. 추가 진입이 자동으로 잠금 상태가 된 것을 확인한다.
4. 사용자가 직접 청산 여부를 판단하고 기록한다.
5. 신호 결과는 실패 또는 무효 표본으로 저장된다.

### 무효 사유 예시

- 당일 저점 이탈
- 프로그램 Bearish Shift
- 최근 5분·15분 프로그램 순매도
- 최대 손실 한도 도달
- Flow Confidence 기준 미달
- 데이터 품질 문제

### 제품 원칙

손실 신호를 숨기거나 결과 검증에서 제외하지 않는다.

---

## 12. 시나리오 9: 장 마감 전 당일 전량청산

### 사용자 상황

목표수익이나 Rally Exit가 발생하지 않았지만 장 마감이 가까워진다.

### 사용자 흐름

1. 사용자가 설정한 마감 전 청산 알림을 받는다.
2. 현재 잔여 수량과 손익을 확인한다.
3. 사용자가 실제 증권 앱에서 전량청산한다.
4. FlowPulse에 청산 내역을 기록한다.
5. 해당 거래가 `당일청산 완료`로 표시된다.

### 예외 상황

다음 날까지 보유한 경우 Playbook 규칙 이탈로 표시하고 당일청산 전략 표본과 분리한다.

## 13. 시나리오 10: 거래 종료 후 사후검증

### 사용자 목표

자신의 판단과 FlowPulse 신호가 실제로 어땠는지 확인한다.

### 사용자 흐름

1. 거래 종료 후 결과 카드를 연다.
2. 신호 발생 후 10분·30분·종가 결과를 확인한다.
3. 자신의 평균 진입가와 청산가를 비교한다.
4. 최대 유리 변동폭과 최대 불리 변동폭을 확인한다.
5. 규칙을 지킨 부분과 이탈한 부분을 확인한다.
6. 같은 신호의 누적 결과와 비교한다.

### 결과 카드 예시

```text
신호 발생가              52,100원
10분 결과                +0.6%
30분 결과                +1.8%
종가 결과                +0.9%

사용자 평균 진입가         52,250원
사용자 평균 청산가         53,180원
사용자 결과               +1.78%

최대 유리 변동폭           +2.4%
최대 불리 변동폭           -0.7%
당일청산                  완료
규칙 이탈                 없음
```

성과 수치는 실제 저장 데이터를 사용하며 임의로 생성하지 않는다.

## 14. 시나리오 11: 최소 수량 또는 모의 검증

### 사용자 상황

새로운 Playbook을 바로 큰 금액으로 사용하지 않고 작동 방식과 손실 가능성을 확인하고 싶다.

### 사용자 흐름

1. 사용자가 `검증 모드`를 선택한다.
2. 모의 기록 또는 최소 수량 기록을 선택한다.
3. 진입·추가 진입·청산 판단을 기록한다.
4. 실제 시장 데이터와 결과를 자동 연결한다.
5. 최소 표본 수가 쌓일 때까지 결과를 누적한다.

### 제품 표현 원칙

`1주씩 해보세요`가 아니라 다음처럼 중립적으로 안내한다.

> 실제 자금을 크게 사용하기 전에 모의 기록 또는 최소 수량으로 전략의 작동 방식과 손실 가능성을 확인할 수 있습니다.

## 15. 시나리오 12: 외국인·기관·개인 신호 사용

### 사용자 목표

프로그램뿐 아니라 선택한 투자 주체의 과매도 매수 유입과 과매수 매도 전환을 확인한다.

### 지원 Playbook

| 투자 주체 | 진입 관찰 | 익절 관찰 |
|---|---|---|
| 외국인 | Foreign Dip Reversal | Foreign Rally Exit |
| 기관 | Institution Dip Reversal | Institution Rally Exit |
| 개인 | Retail Dip Reversal | Retail Rally Exit |

### 사용자 흐름

1. 사용자가 분석 주체를 선택한다.
2. 해당 주체의 Flow Shift·Divergence·Persistence를 확인한다.
3. 다른 주체와의 Flow Sync를 확인한다.
4. 주체별 데이터 갱신 주기와 Confidence를 확인한다.
5. 선택한 Playbook을 관찰하거나 알림을 설정한다.

### 중요 예외

개인 순매수는 외국인·기관의 매도를 받아내는 잔여 흐름일 수 있으므로 자동으로 긍정 신호로 해석하지 않는다. 다른 주체의 방향과 시장 국면을 함께 표시한다.

---

## 16. 시나리오 13: 여러 주체가 동시에 전환되는 복합 신호

### 사용자 상황

외국인·기관·프로그램이 비슷한 시점에 매수 또는 매도 방향으로 전환한다.

### 사용자 흐름

1. Flow Sync 급상승 또는 급하락 알림을 받는다.
2. 각 주체별 방향과 기여도를 확인한다.
3. 동일 시간축에서 전환 시점을 확인한다.
4. 가격·거래량 확인 조건을 확인한다.
5. 단일 주체 신호보다 높은 Confidence가 정당한지 근거를 확인한다.

### 제품 표시 예시

```text
Flow Sync             +76 · 강한 매수 동조
외국인                Bullish Shift
기관                  매수 유지
프로그램              Bullish Shift
개인                  순매도
Flow Confidence       86/100
```

## 17. 시나리오 14: 관심 종목 수급 변화 알림

### 사용자 흐름

1. 사용자가 종목을 관심 목록에 저장한다.
2. 확인할 투자 주체와 신호 유형을 선택한다.
3. 알림 최소 Confidence와 방해 금지 시간을 설정한다.
4. 방향 전환·동조·무효 조건 알림을 받는다.
5. 알림에서 바로 신호 카드와 차트 시점으로 이동한다.

### 알림 제어

- 동일 신호 반복 알림 제한
- 중요 상태 변화에만 알림
- 사용자가 설정한 시간대 준수
- 데이터 지연 시 알림에 경고 포함

## 18. 시나리오 15: Feed에 당시 데이터와 의견 공유

### 사용자 흐름

1. 종목 상세 또는 신호 결과에서 `Feed에 공유`를 선택한다.
2. 작성 당시 가격·수급·Flow 지표·차트 구간을 첨부한다.
3. 사용자가 자신의 관찰과 조건을 작성한다.
4. 글 게시 후 당시 데이터는 고정 보존한다.
5. 10분·30분·종가 및 후속 결과가 자동 연결된다.

### Feed 구분

- 국내주식
- 해외주식
- 자유

종목별 토론은 종목 상세에 연결된 Feed로 제공한다.

## 19. 시나리오 16: 데이터 지연·누락·불일치

### 사용자 상황

API 연결 단절, 갱신 지연 또는 공급사 데이터 불일치가 발생한다.

### 제품 동작

1. 마지막 정상 갱신 시각을 표시한다.
2. 영향받는 지표와 신호를 식별한다.
3. Flow Confidence를 낮추거나 계산을 중단한다.
4. 강한 신호 알림을 차단한다.
5. AI 해설에 데이터 한계를 표시하거나 생성을 중단한다.
6. 연결 복구 후 누락분을 보완하고 재계산 여부를 기록한다.

### 표시 예시

```text
데이터 지연
프로그램 데이터가 47초 동안 갱신되지 않았습니다.
현재 신호를 확정할 수 없습니다.
```

## 20. 시나리오 17: AI 해설을 사용할 수 없는 경우

- AI 장애를 핵심 데이터 장애처럼 보이게 하지 않는다.
- 이전 해설을 최신 해설처럼 재사용하지 않는다.

### 표시 예시

```text
AI 해설을 불러오지 못했습니다.
원본 데이터와 계산된 신호는 정상적으로 확인할 수 있습니다.
```

## 24. 시나리오 기반 MVP 완료 기준

MVP는 다음 흐름을 실제 데이터 또는 명확히 구분된 테스트 데이터로 처음부터 끝까지 수행할 수 있어야 한다.

```text
후보 탐지
→ 핵심 카드 표시
→ 근거와 차트 시점 확인
→ 사용자 판단 기록
→ 분할진입 상태 관리
→ 수급 변화 알림
→ 익절·손절·시간청산 기록
→ 사후 결과 검증
```

각 단계에서 다음을 충족해야 한다.

- 기준 시각 표시
- 데이터 출처 및 지연 상태 추적
- 핵심 지표 계산 근거 확인
- 반대 근거와 무효 조건 표시
- 모바일 웹과 앱에서 동일한 핵심 흐름 제공
- 연결 단절 후 복구
- 사용자의 직접 주문 원칙 유지
