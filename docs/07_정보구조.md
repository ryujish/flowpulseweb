## 1. 문서 목적

이 문서는 FlowPulse의 메뉴·화면·콘텐츠 계층·탐색 경로·신호 상태·데이터 상태를 정의한다.

정보구조의 목표는 사용자가 짧은 시간 안에 다음 질문에 답하게 하는 것이다.

1. 지금 시장에서 누가 사고 팔고 있는가
2. 방향이 전환되었는가
3. 여러 투자 주체가 같은 방향인가
4. 어떤 종목에 중요한 신호가 발생했는가
5. 신호를 얼마나 신뢰할 수 있는가
6. 무엇을 확인하고 언제 무효가 되는가
7. 사용자의 판단과 실제 결과는 어땠는가

---

## 2. 정보구조 원칙

1. 시장 → 종목 → 신호 → 근거 → 기록 → 검증 순서로 깊어진다.
2. 첫 화면에는 결론과 상태를, 상세 화면에는 수치와 계산 근거를 둔다.
3. 원본 데이터·Flow 계산·AI 해석을 시각적으로 구분한다.
4. 상승 근거와 반대 근거를 같은 깊이에서 확인할 수 있게 한다.
5. 모든 신호에는 기준 시각·데이터 상태·무효 조건을 연결한다.
6. 사용자의 주문을 대신하지 않고 판단과 기록을 지원한다.
7. 모바일에서 핵심 흐름을 3단계 이내에 도달하게 한다.

## 3. 전역 내비게이션

하단 메뉴는 5개로 고정한다.

| 메뉴 | 목적 | 대표 질문 |
|---|---|---|
| Flow | 시장과 핵심 신호 발견 | 지금 중요한 흐름은 무엇인가 |
| 종목 | 검색·관심·종목 분석 | 이 종목의 수급은 어떤가 |
| AI | 근거 기반 질의와 해설 | 이 변화는 왜 발생했나 |
| Feed | 데이터가 연결된 의견 | 다른 사용자는 무엇을 관찰했나 |
| Me | 기록·알림·연결·설정 | 나의 판단과 결과는 어땠나 |

모바일에서는 하단 탭, PC에서는 좌측 내비게이션으로 표현하되 정보구조와 명칭은 동일하게 유지한다.

## 5. Flow 홈 정보계층

Flow 홈은 `시장 요약 → 핵심 신호 → 종목 발견 → 상세 진입` 순서로 구성한다.

### 1단계: 시스템·데이터 상태

- 장 운영 상태
- 마지막 갱신 시각
- 실시간·지연·추정 상태
- 연결 오류 배너

정상일 때는 작게 표시하고 문제가 있을 때 상단 배너로 확장한다.

### 2단계: 오늘 시장 한 문장

```text
외국인 매도는 약해지고 프로그램 매수는 강화되지만 기관 동조는 아직 제한적입니다.
```

AI 문장 아래에 기준 시각과 Confidence를 표시한다.

### 3단계: 시장 Flow 지표

- 외국인 Flow Shift
- 기관 Flow Shift
- 개인 Flow Shift
- 프로그램 Flow Shift
- Core Flow Sync
- 시장 Flow Confidence

### 4단계: 대표 Playbook

- Program Dip Reversal 후보
- Program Rally Exit 활성 종목
- 향후 공개된 Actor Playbook

### 5단계: 수급 급변 종목

- Flow Acceleration 상위
- Flow Divergence 상위
- Bullish/Bearish Shift 발생 종목

### 6단계: 관심 종목

- 현재가
- 선택 주체 Shift
- Confidence
- 활성 신호

## 6. Flow 홈 카드 우선순위

| 우선순위 | 카드 | 표시 조건 |
|---:|---|---|
| 1 | 데이터 장애 | STALE·MISSING·연결 단절 |
| 2 | 장 마감 전 청산 | 활성 데이트레이딩 기록 존재 |
| 3 | 신호 무효·위험 | Hard Invalidation 발생 |
| 4 | Program Rally Exit | 보유기록 + 청산 조건 |
| 5 | Program Dip Reversal | 진입 확인 조건 후보 |
| 6 | 시장 Flow 브리핑 | 항상 |
| 7 | 수급 급변 종목 | 후보 존재 시 |
| 8 | 관심 종목 | 사용자 설정 시 |

수익 기회보다 데이터 장애와 위험 조건을 위에 배치한다.

1. Flow Shift

4. Flow Divergence

### 영역 D: 확인·위험

## 11. 투자 주체별 수급 패널

각 주체는 동일한 정보 구조를 사용한다.

```text
프로그램
├─ 현재 방향
├─ 누적 순매수
├─ 최근 5분·15분 변화량
├─ 거래대금 대비 비율
├─ Flow Shift
├─ Persistence
├─ Acceleration
└─ 데이터 상태
```

개인 수급에는 다음 안내를 추가한다.

> 개인 순매수는 다른 주체의 매도를 받아내는 흐름일 수 있어 단독으로 긍정 신호로 해석하지 않습니다.

## 15. 기록 흐름

```text
관찰 시작
→ 1차 진입 기록
→ 추가 진입 조건 확인
→ 2~5차 기록
→ 수익 보호 또는 위험 알림
→ 부분청산 기록
→ 전량청산 기록
→ 사후검증
```

### 기록 입력 최소화

- 가격 자동 제안, 사용자가 수정 가능
- 수량 또는 비중 입력
- 이유는 선택형 Reason Code 우선
- 메모는 선택사항

원본 시세 사용권한이 없거나 데이터가 지연될 때 자동 제안값의 상태를 표시한다.

## 22. 데이터 상태 정보구조

모든 데이터는 다음 상태 중 하나를 가진다.

- REALTIME
- DELAYED
- ESTIMATED
- FINAL
- STALE
- MISSING
- CORRECTED

### 표시 계층

- 정상: 기준 시각 옆 작은 라벨
- 지연·추정: 카드 헤더 경고
- Stale·Missing: 화면 상단 배너와 신호 중단
- Corrected: 사후검증 상세에 정정 이력

0이나 빈칸으로 데이터 부재를 표현하지 않는다.

## 33. 정보구조 완료 기준

1. 핵심 사용자 시나리오가 3단계 이내 주요 상세에 도달한다.
2. 신호 카드에 공통 지표와 무효 조건이 포함된다.
3. 원본 데이터·Flow 계산·AI 해석이 구분된다.
4. 모든 핵심 화면에 기준 시각과 데이터 상태가 존재한다.
5. 진입과 청산이 같은 Playbook 흐름에 연결된다.
6. 사용자 기록과 사후검증이 연결된다.
7. BYOK 연결과 해제·삭제 경로가 있다.
8. 빈 상태·오류·지연·추정 상태가 정의된다.
9. 모바일과 PC가 같은 의미 구조를 사용한다.
10. 자동주문 경로가 존재하지 않는다.
