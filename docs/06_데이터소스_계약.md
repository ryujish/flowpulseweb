## 1. 문서 목적

이 문서는 FlowPulse에서 필요한 데이터를 어디서 확보하고, 어떤 범위까지 수집·저장·가공·표시·재배포할 수 있는지 검증하기 위한 기준을 정의한다.

데이터 API가 기술적으로 호출된다는 사실과 서비스에서 합법적으로 사용할 수 있다는 사실은 다르다. 따라서 다음을 별도로 확인한다.

1. 데이터 항목 제공 여부
2. 실시간·지연·추정·확정 구분
3. 개인 개발과 상용 서비스 허용 범위
4. 서버 저장과 보관 기간
5. 지표 계산 등 2차 가공
6. 외부 사용자 화면 표시와 재배포
7. 캐시·백테스트·사후검증 사용
8. 출처 표시 의무
9. 호출 제한·동시접속·장애 정책
10. 비용·계약·승인 절차

공식 공개자료에서 확인되지 않는 사항은 추측하지 않고 `공급사 서면 확인 필요`로 표시한다.

## 2. 핵심 결론

### 폐쇄형 MVP

개인 개발자의 계정과 API 키를 사용하여 본인만 접근하는 폐쇄형 환경에서 데이터 수집, 지표 계산, 화면 검증, 백테스트 구조를 개발한다.

### 공개 서비스

불특정 사용자가 접속하는 웹·앱 서비스로 전환하기 전 다음이 필요하다.

- 증권사 API의 상용·제3자 제공 허용 여부 서면 확인
- KRX 시장정보의 수신·가공·재배포 계약 검토
- 필요한 경우 코스콤 및 한국거래소 승인·계약
- 뉴스 원문·요약·링크 표시 권한 확인
- 데이터별 출처·지연·확정 상태 표시

### 가장 중요한 원칙

> 개인용 API로 기능을 개발할 수 있다는 사실을 공개 서비스의 재배포 권한으로 해석하지 않는다.

## 3. 제품 단계별 데이터 사용 구분

| 단계 | 사용자 범위 | 허용 데이터 전략 |
|---|---|---|
| 로컬 실험 | 개발자 1인 | 개인 API·공개 API로 제한적 검증 |
| 폐쇄형 MVP | 승인된 내부 사용자 | 약관 범위 내 테스트, 외부 재배포 금지 |
| 비공개 베타 | 제한된 외부 사용자 | 공급사 서면 승인 또는 별도 계약 필요 |
| 공개 서비스 | 불특정 다수 | 정식 상용·재배포 계약 필수 |
| 유료 서비스 | 구독·광고·B2B | 상업적 이용·가공·재배포 범위 계약 명시 |

`무료 공개 서비스`도 제3자 제공에 해당할 수 있으므로 유료 여부만으로 판단하지 않는다.

## 4. 데이터 역할 분리

| 데이터 영역 | 1차 후보 | FlowPulse 용도 |
|---|---|---|
| 현재가·체결·호가 | 증권사 API·정식 시장정보 | 실시간 가격과 차트 |
| 분봉 | 증권사 API·정식 시장정보 | 5분·15분·30분 계산 |
| 프로그램 매매 | 증권사 API·정식 시장정보 | Program Playbook |
| 외국인·기관·개인 수급 | 증권사 API·정식 시장정보 | Actor Flow 엔진 |
| 시장 통계·공식 일별 데이터 | KRX Data Marketplace | 검증·기준 데이터 |
| 공시·재무 | OpenDART | 기업 이벤트와 재무정보 |
| 시장조치 | KRX·KIND | 거래정지·관리·공시 이벤트 |
| 뉴스 검색 | 네이버 검색 API 등 | 기사 제목·요약·링크 탐색 |
| 독자 지표 | FlowPulse 자체 계산 | Shift·Sync·Confidence 등 |
| 사용자 기록 | FlowPulse 자체 데이터 | 진입·청산·사후검증 |

OpenDART를 현재가·분봉·호가·체결·실시간 수급 소스로 사용하지 않는다.

## 5. 한국투자증권 Open API

### 공식 공개자료에서 확인된 제공 항목

KIS Developers API 카탈로그에는 다음 항목이 공개되어 있다.

- 국내주식 실시간 체결가·호가
- 국내주식 실시간 프로그램매매
- 종목별 프로그램매매추이(체결·일별)
- 프로그램매매 종합현황(시간·일별)
- 프로그램매매 투자자매매동향(당일)
- 국내기관·외국인 매매종목 가집계
- 종목별 외인기관 추정가집계
- 시장별 투자자매매동향
- 회원사 실시간 매매동향

따라서 기술적 후보로는 FlowPulse의 가격·프로그램·일부 투자자 수급 검증에 가장 가깝다.

### FlowPulse 활용 후보

| 데이터 | 폐쇄형 MVP 용도 |
|---|---|
| 실시간 체결가 | 현재가, OHLCV 생성, 가격 확인 |
| 실시간 프로그램매매 | 프로그램 누적·구간 변화량 |
| 프로그램 체결 추이 | Program Dip/Rally 검증 |
| 외인기관 추정가집계 | Actor 지표 실험 |
| 시장 투자자 동향 | 시장 Flow Sync |

### 아직 확인되지 않은 사항

공개 API 목록만으로 다음을 확정할 수 없다.

- 불특정 사용자 대상 화면 재표시 허용
- 원본 데이터 서버 장기 저장 허용
- 분봉 재구성 및 장기 보관 허용
- Flow 지표 계산 후 유료 제공 허용
- 다수 사용자에게 WebSocket으로 재전송 허용
- 상용 서비스 호출량과 동시접속 한도
- 개인 앱 키를 법인 서비스에서 사용할 수 있는지
- 외국인·기관·개인 데이터가 실시간 확정값인지 추정값인지

모두 `한국투자증권 서면 확인 필요`다.

### 초기 판단

- 폐쇄형 개인 MVP: 사용 가능성 높음, 실제 약관과 계정 권한 확인 필요
- 외부 베타: 사전 서면 승인 없이는 진행하지 않음
- 공개·유료 서비스: 별도 제휴 또는 데이터 계약 필요 가능성이 높음

마지막 문장은 공개 자료를 바탕으로 한 신중한 판단이며 계약 확정 사실이 아니다.

## 6. KRX Data Marketplace Open API

### 공식 약관에서 확인된 사항

2026-08-10 확인 기준 KRX Open API 약관은 다음을 명시한다.

- 인증키 신청과 약관 동의 필요
- 이용기간은 인증키 제공일부터 1년이며 연장 요청 가능
- 비상업적 목적만 이용 가능
- API 결과에 대한 대가를 제3자에게 청구할 수 없음
- API 정보를 제3자에게 제공할 수 없음
- 화면 제작 시 `한국거래소 통계정보` 사용 결과임을 표시
- 키당 하루 10,000회 이하 요청 제한
- 정보의 오류·누락·장애에 대한 정확성과 완결성을 보장하지 않음

### 제품 영향

KRX Open API는 다음 용도로 제한한다.

- 개발자 내부 검증
- 공식 일별 데이터 대조
- 백테스트 기준 데이터 검토
- 시장 통계 검증

KRX Open API 응답을 공개 FlowPulse 사용자에게 그대로 제공하거나 유료 서비스의 핵심 데이터로 사용하는 것은 현재 공개 약관과 충돌할 수 있다.

### 실시간 시장정보 계약

KRX 공식 안내는 개인이 단순 참고가 아니라 재배포 프로그램 개발·수익사업 등 목적으로 시세정보를 사용하려면 별도 계약이 필요하다고 안내한다.

전문 이용자는 일반적으로 다음 절차를 거친다.

1. 코스콤에 정보이용 신청
2. 한국거래소 정보이용 승인
3. 코스콤과 계약 체결
4. 데이터 직접 또는 간접 수신

따라서 KRX Open API와 정식 실시간 시장정보 계약을 동일한 것으로 취급하지 않는다.

## 7. 코스콤·KRX 정식 시장정보

### 검토 목적

공개 FlowPulse가 실시간·지연 시세와 수급 데이터를 다수 사용자에게 표시하려면 정식 시장정보 계약 경로를 검토해야 한다.

### 문의해야 할 데이터

- KRX·NXT 현재가·체결·호가
- 종목별 프로그램 매매
- 시장 프로그램 차익·비차익
- 외국인·기관·개인 장중 수급
- 시장별 투자자 수급
- 지수와 ETF 관련 데이터

### 계약 문의 항목

- 직접수신·간접수신 방식
- 실시간·20분 지연·종가 데이터 구분
- 웹·모바일·WebView 사용자 표시 권한
- 가입자 수 또는 단말 수 과금
- 비가입자·회원 구분
- 유료 구독 서비스 허용 범위
- 원본 데이터 저장 기간
- 차트·분봉 재구성
- 독자 지표와 AI 설명으로 가공
- 원본 수치와 가공 점수 동시 표시
- 백테스트와 사후검증 장기 보관
- 스크린샷·공유 카드·Feed 첨부
- 해외 접속 사용자 제공
- 감사 로그·사용량 보고 의무

계약서에 없는 권리는 허용된 것으로 가정하지 않는다.

## 8. OpenDART

### 공식 공개자료에서 확인된 범위

OpenDART는 개인·기업·기관 등이 DART 공시원문과 주요 공시·재무정보를 API, XML, XBRL 등으로 활용할 수 있도록 제공한다.

### FlowPulse 용도

- 공시 목록과 원문 링크
- 주요사항보고서
- 지분공시
- 정기보고서 주요 항목
- 재무제표·주요 재무계정
- 종목 이벤트 타임라인

### 사용하지 않는 용도

- 현재가
- 실시간 체결·호가
- 1분·5분·30분봉
- 장중 프로그램매매
- 장중 외국인·기관·개인 수급

### 확인 필요

- 인증키 호출한도
- 원문 저장과 캐시 정책
- 대량 수집 허용 범위
- 화면 출처 표시 형식
- 공시 첨부파일 재제공 범위

공시 원문 전체를 FlowPulse가 재호스팅하기보다 원문 링크와 필요한 구조화 정보 중심으로 시작한다.

## 9. KRX·KIND 시장조치

### 용도

- 거래정지
- 관리종목·투자주의·경고·위험
- 상장폐지 및 기업행동
- 공식 공시와 시장조치

### 제품 반영

시장조치는 다음 기능에 직접 연결한다.

- Program Playbook 후보 제외
- 추가 진입 잠금
- Risk/Invalidation
- 종목 상세 경고
- 사후검증 예외 구분

### 확인 필요

- 데이터 접근 방식
- 자동 수집 허용 범위
- 저장·가공·표시 권한
- 갱신 주기
- 출처 표시

웹페이지 스크래핑을 기본 데이터 계약으로 간주하지 않는다.

## 10. 네이버 뉴스 검색 API

### 공식 문서에서 확인된 사항

- 뉴스 검색 결과를 JSON 또는 XML로 반환
- 애플리케이션 등록과 Client ID·Secret 필요
- 검색 API 하루 호출 한도 25,000회
- 기사 제목·원문 링크·네이버 링크·요약 패시지·제공 시각 필드 제공

### FlowPulse 용도

- 종목 관련 최신 뉴스 검색
- 기사 제목·출처·발행시각·링크 표시
- 수급 급변 시점 주변 뉴스 탐색

### 제품 원칙

- 기사 원문 전체를 저장·재배포하지 않음
- 검색 결과 요약 패시지를 AI 원문처럼 취급하지 않음
- AI가 기사를 분석할 권한과 원문 접근 범위를 별도 확인
- 출처와 원문 링크를 표시
- 중복 기사 제거와 시간대 정규화

### 확인 필요

- 검색 결과 장기 저장 허용 범위
- 요약 패시지 재표시·가공 범위
- 상용 서비스에서의 표시 요건
- 뉴스 제공사별 저작권

뉴스는 P0 핵심 수급 엔진의 필수 입력이 아니라 보조 설명 데이터로 둔다.

## 11. 토스·KB증권 등 대체 증권사 API

### 현재 상태

FlowPulse에 필요한 공개 API 제공 항목, 개인 개발자 접근성, 상용 재배포 권한을 공식 자료로 아직 확정하지 못했다.

따라서 다음을 확인하기 전에는 데이터 소스로 확정하지 않는다.

- 공개 개발자 API 존재 여부
- 실시간 체결·호가
- 종목별 프로그램매매
- 외국인·기관·개인 장중 수급
- WebSocket 지원
- 개인·법인 신청 조건
- 상용·제3자 제공
- 저장·가공·재배포
- 비용과 호출 제한

`가능할 것`이라는 추측으로 아키텍처를 결정하지 않는다.

## 12. 데이터소스 우선순위

### 폐쇄형 MVP

1. 한국투자증권 Open API로 가격·프로그램 데이터 기술 검증
2. 외인·기관 추정 데이터의 실제 필드와 갱신주기 확인
3. KRX Open API로 일별·공식 데이터 대조
4. OpenDART로 공시·재무 연결
5. KRX·KIND 시장조치 연결
6. 뉴스 검색은 후순위 보조 기능

### 공개 서비스

1. 정식 시장정보 이용계약 견적
2. 증권사 또는 데이터벤더 제휴
3. 저장·가공·재배포 권한 문서화
4. 계약 범위에 맞춘 공개 기능 확정
5. 데이터별 출처·지연 라벨 적용

## 13. Flow 지표별 최소 데이터

| 지표 | 필수 데이터 | 데이터가 없을 때 |
|---|---|---|
| Flow Shift | 주체별 누적·5분·15분 수급 | 해당 주체 계산 중단 |
| Flow Sync | 2개 이상 유효 주체 방향 | Neutral 또는 미제공 |
| Flow Confidence | 품질·지연·표본 메타데이터 | 신호 확정 금지 |
| Flow Divergence | 가격수익률·주체 방향점수 | 미제공 |
| Flow Persistence | 연속 구간 수급 | 미제공 |
| Flow Acceleration | 현재·직전 구간 변화량 | 미제공 |
| Program Dip | 프로그램·가격·거래대금·Envelope | 후보 생성 금지 |
| Program Rally Exit | 보유기록·프로그램·가격 | 동적 익절 미제공 |

데이터가 없을 때 0으로 대체하지 않는다. `없음`, `지연`, `계산 불가`를 구분한다.

## 14. 실시간·추정·확정 데이터 정책

### 필수 상태

| 상태 | 의미 |
|---|---|
| REALTIME | 계약상 실시간 데이터 |
| DELAYED | 명시된 지연시간이 있는 데이터 |
| ESTIMATED | 장중 추정 또는 가집계 데이터 |
| FINAL | 사후 확정 데이터 |
| STALE | 허용 지연 초과 |
| MISSING | 데이터 누락 |
| CORRECTED | 공급사 정정 반영 |

### 사용자 표시

```text
프로그램 수급 · 실시간 · 10:24:15
외국인 수급 · 장중 추정 · 10:23
기관 수급 · 1분 지연 · 10:23
```

확정값이 들어오면 장중 추정값을 덮어쓰기만 하지 않고 정정 이력을 보존한다.

## 15. 저장 계층

### Raw Layer

- 공급사 원본 응답 또는 허용된 최소 원본 필드
- 공급사 기준 시각과 수신 시각
- 출처·계약 ID·데이터 상태

### Normalized Layer

- 공통 종목코드
- 표준 시각
- 표준 단위
- 중복·역순 처리 결과

### Derived Layer

- Flow 지표
- Envelope
- Playbook 상태
- Reason Code

### Snapshot Layer

- 신호 발생 당시 데이터
- AI 해설 입력
- 사용자 기록
- 사후검증 결과

원본 저장이 계약상 제한되면 Raw Layer의 저장 범위와 TTL을 계약에 맞춰 축소한다. Derived Layer라고 해서 자동으로 자유로운 재배포 권리가 생기는 것은 아니다.

## 16. 데이터 보관 정책

보관 기간은 기술 편의가 아니라 계약별 허용 범위로 결정한다.

| 데이터 유형 | 희망 보관 | 계약 확인 |
|---|---|---|
| 실시간 원본 체결 | 백테스트 필요 기간 | 필수 |
| 분봉 | 장기 사후검증 | 필수 |
| 수급 원본 | 장기 지표 재계산 | 필수 |
| 독자 지표 | 장기 | 원본 권리와 연계 확인 |
| 신호 스냅샷 | 장기 | 원본 필드 포함 범위 확인 |
| 공시 메타데이터 | 장기 | OpenDART 약관 확인 |
| 뉴스 검색 결과 | 최소 기간 | API·언론사 권리 확인 |
| 사용자 기록 | 사용자 탈퇴·삭제 정책 | 개인정보 정책 적용 |

계약상 보관 기간을 넘긴 원본은 삭제 또는 비식별·집계 데이터로 전환해야 할 수 있다.

## 17. 가공 데이터 정책

FlowPulse가 생성하는 다음 데이터는 자체 계산 결과다.

- Flow Shift
- Flow Sync
- Flow Confidence
- Flow Divergence
- Flow Persistence
- Flow Acceleration
- Program Dip/Rally 상태
- 사후검증 집계

그러나 원본 시장정보에서 파생된 값이라는 이유로 계약 제한과 무관하다고 단정할 수 없다.

공급사에 다음을 서면으로 확인한다.

- 원본 수치를 노출하지 않고 점수만 제공 가능한가
- 방향 상태 문구만 제공 가능한가
- 차트에 가공선을 표시 가능한가
- AI 설명에 원본 수치를 포함 가능한가
- 공유 카드에 지표와 당시 가격을 포함 가능한가
- 장기 사후검증 통계를 공개 가능한가

## 18. 재배포 판단 기준

다음 중 하나라도 해당하면 재배포로 간주될 가능성을 검토한다.

- 다수 사용자 화면에 원본 시세 표시
- 서버가 증권사 데이터를 받아 앱에 중계
- WebSocket으로 체결·수급 변경분 전송
- Feed 글에 당시 시세 스냅샷 첨부
- 공유 이미지에 가격·수급 수치 포함
- 유료 구독자에게 실시간 지표 제공
- B2B API로 Flow 지표 제공

`원본 데이터를 조금 가공했다`는 이유만으로 재배포가 아니라고 판단하지 않는다.

## 20. API 키와 인증정보

- API 키를 브라우저·WebView·모바일 앱에 포함하지 않는다.
- 모든 공급사 호출은 서버에서 수행한다.
- 개발·스테이징·운영 키를 분리한다.
- 키를 소스코드와 Git 저장소에 커밋하지 않는다.
- Secret Manager 또는 안전한 환경변수 저장소를 사용한다.
- 키별 호출량과 오류를 모니터링한다.
- 퇴사·계약종료·키유출 시 즉시 회수 절차를 둔다.
- 개인 계정 키와 법인 운영 키를 분리한다.

인증키 양도·공유가 금지된 서비스에서는 팀 공용 키처럼 사용하지 않는다.

## 21. 호출 제한과 수집 전략

### KRX Open API

공식 약관 기준 키당 하루 10,000회 이하 제한을 고려한다.

### 네이버 검색 API

공식 문서 기준 검색 API 하루 25,000회 제한을 고려한다.

### 증권사 API

엔드포인트별 초당·분당·일별 제한과 WebSocket 등록 종목 제한은 실제 문서와 계정 권한으로 확인한다.

### 수집 원칙

- 사용자마다 공급사 API를 중복 호출하지 않음
- 서버에서 한 번 수집하고 허용 범위 안에서 내부 계산
- REST는 초기 스냅샷
- WebSocket은 변경분
- 호출 제한 초과 전 백오프
- 장 시작·종료와 동시호가 상태 반영
- 무한 재시도 금지

허용 범위를 넘는 서버 중계는 계약 전에는 외부 사용자에게 제공하지 않는다.

- 보관 기간 제한이 있는가
- 분봉으로 재구성 가능한가
- 백테스트에 사용할 수 있는가
- 사후검증 스냅샷을 장기 보관할 수 있는가

- 독자 지표 계산이 가능한가
- AI 해설 입력으로 사용 가능한가

- 파생 결과의 소유권과 제공 범위는 무엇인가

### 재배포

- 웹·iOS·Android에 표시 가능한가
- 무료·유료 사용자 구분은 무엇인가
- 원본 수치·차트·점수별 허용 범위는 무엇인가
- Feed·스크린샷·공유 카드가 가능한가
- B2B API 제공이 가능한가

### 운영

- 호출 제한과 동시접속 제한
- SLA·장애 통지
- 비용·최소 계약기간
- 사용자 수·단말 수 보고
- 출처 표시
- 계약 종료 후 데이터 처리

## 29. 출시 차단 조건

다음 중 하나라도 해당하면 해당 데이터 기반 기능의 공개 출시를 차단한다.

- 외부 사용자 재배포 권한 미확인
- 개인 API 키를 공개 서비스에서 무단 사용
- 저장 기간과 가공 권한 미확인
- 실시간·지연·추정 상태 미표시
- 출처 표시 의무 미반영
- API 키 클라이언트 노출
- 계약 허용량을 초과하는 호출 설계
- 원문 뉴스 무단 저장·재배포
- KRX Open API를 상업 서비스 원본으로 무단 사용

---

## 30. 현재 확정된 사항

1. OpenDART는 공시·재무 영역에만 사용한다.
2. 현재가·분봉·호가·체결·수급은 증권사 API 또는 정식 시장정보로 확보한다.
3. 시장조치는 KRX·KIND로 분리한다.
4. 개인 API는 본인 전용 폐쇄형 MVP 검증에만 사용한다.
5. 공개 서비스 전에 저장·가공·재배포 권한을 확인한다.
6. KIS API 카탈로그에는 FlowPulse에 필요한 프로그램·일부 투자자 데이터 후보가 존재한다.
7. KRX Open API는 공개·상업 서비스의 정식 실시간 재배포 계약을 대체하지 않는다.
8. 서버는 개발자 노트북과 무관하게 상시 수집한다.
9. 데이터 출처·기준 시각·지연·추정 여부를 표시한다.
10. 권한이 불명확하면 기능을 공개하지 않는다.

---

## 31. 현재 미확정 사항

- 한국투자증권 데이터의 상용·제3자 제공 허용 범위
- 종목별 외국인·기관·개인의 장중 정확도와 갱신주기
- KRX·코스콤 정식 데이터 계약 비용
- 사용자 수·단말 수 과금 구조
- 원본 데이터 보관 기간
- Flow 지표와 AI 해설의 파생 데이터 권리
- Feed·공유 카드의 당시 데이터 포함 권한
- KB증권·토스증권 등 대체 API 가능 여부
- 네이버 뉴스 검색 결과의 장기 저장·가공 범위

현재 공개자료만으로는 위 사항을 확정할 수 없다.
