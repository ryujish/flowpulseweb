## 1. 문서 목적

이 문서는 FlowPulse의 핵심 지표와 대표 Playbook을 실제 구현 가능한 계산 구조로 정의한다.

대상은 다음과 같다.

- Flow Shift
- Flow Sync
- Flow Confidence
- Flow Divergence
- Flow Persistence
- Flow Acceleration
- Flow Impact
- Signal Phase
- Risk/Invalidation
- Program Dip Reversal
- Program Rally Exit

이 문서의 숫자 가중치와 임계값은 **초기 구현값이며 검증 전 확정값이 아니다.** 과거 데이터 백테스트, 장중 모의운영, 거래비용과 슬리피지 반영 결과에 따라 버전별로 조정한다.

## 2. 핵심 설계 원칙

1. 절대 순매수 금액만 사용하지 않는다.
2. 종목별 거래대금과 유동성 차이를 정규화한다.
3. 누적 흐름과 최근 5분·15분 흐름을 분리한다.
4. 매도 약화와 매수 전환을 구분한다.
5. 매수 약화와 매도 전환을 구분한다.
6. 프로그램·외국인·기관·개인을 같은 엔진으로 계산하되 임계값은 따로 검증한다.
7. 가격 상태와 수급 상태를 함께 확인한다.
8. 데이터 품질이 낮으면 신호 강도를 높이지 않는다.
9. 모든 계산은 당시 이용 가능했던 데이터만 사용한다.
10. 계산식·입력·임계값·결과에 버전을 부여한다.

## 3. 용어와 기호

### 투자 주체

| 기호 | 투자 주체 |
|---|---|
| `P` | 프로그램 |
| `F` | 외국인 |
| `I` | 기관 |
| `R` | 개인 |

### 기본 기호

| 기호 | 의미 |
|---|---|
| `t` | 계산 기준 시각 |
| `a` | 투자 주체 |
| `N_a(t)` | 시각 `t`의 누적 순매수 금액 |
| `ΔN_a(t,h)` | 최근 `h`분 순매수 변화량 |
| `V(t,h)` | 최근 `h`분 거래대금 |
| `P(t)` | 현재 가격 |
| `R_p(t,h)` | 최근 `h`분 가격수익률 |
| `Q_a(t)` | 투자 주체별 데이터 품질 점수 |

순매수는 양수, 순매도는 음수로 표현한다.

## 4. 필수 원본 데이터

### 종목·가격

- 종목코드·시장·거래상태
- 현재가·시가·고가·저가·종가
- 1분 또는 원천 체결 기반 OHLCV
- 5분·15분·30분 OHLCV
- 누적 거래량·거래대금

### 수급

- 프로그램 누적 순매수
- 가능한 경우 프로그램 차익·비차익 구분
- 외국인 누적 및 구간별 순매수
- 기관 누적 및 구간별 순매수
- 개인 누적 및 구간별 순매수

### 데이터 상태

- 공급사 기준 시각
- 서버 수신 시각
- 확정값·추정값 구분
- 지연시간
- 누락 구간
- 정정 여부
- 데이터 출처

## 5. 시간 구간

MVP 기본 구간은 다음과 같다.

| 구간 | 역할 |
|---|---|
| 1분 | 원천 변화 탐지와 데이터 품질 확인 |
| 5분 | 가장 최근 수급 방향과 진입·청산 확인 |
| 15분 | 단기 지속성과 노이즈 필터 |
| 30분 | 가격 과매도·과매수 및 큰 흐름 확인 |
| 당일 누적 | 주체별 전체 방향과 규모 |

1분 신호만으로 사용자 알림을 확정하지 않는다. 기본적으로 5분 흐름을 사용자 신호 단위로 사용하고 15분·30분을 확인 구간으로 사용한다.

## 6. 수급 변화량

최근 `h`분 순매수 변화량은 다음과 같다.

```text
ΔN_a(t,h) = N_a(t) - N_a(t-h)
```

예시:

```text
프로그램 누적 순매수 10:20  +7.1억원
프로그램 누적 순매수 10:25  +8.2억원
최근 5분 변화량              +1.1억원
```

누적 순매수가 양수이더라도 최근 변화량이 음수라면 현재는 매도 중일 수 있다. 누적값과 구간 변화량을 반드시 별도로 저장한다.

---

## 7. 거래대금 정규화

동일한 순매수 금액도 종목 거래대금에 따라 의미가 다르다.

### Flow Ratio

```text
FlowRatio_a(t,h) = ΔN_a(t,h) / max(V(t,h), ε)
```

- 양수: 해당 주체 순매수
- 음수: 해당 주체 순매도
- 절대값이 클수록 거래대금 대비 영향이 큼
- `ε`는 0 나눗셈 방지용 최소값

당일 누적 비율:

```text
CumFlowRatio_a(t) = N_a(t) / max(당일 누적 거래대금, ε)
```

절대금액 기준과 거래대금 비율 기준을 함께 사용한다. 저유동성 종목에서 비율이 과도하게 커지는 문제는 최소 거래대금 조건과 상한값으로 제한한다.

---

## 8. 표준화 방식

종목과 시간대에 따른 차이를 줄이기 위해 순매수 비율을 과거 동일 시간대 분포와 비교한다.

### Robust Z-Score

```text
RobustZ(x) = (x - median(x_history)) / max(1.4826 × MAD(x_history), ε)
```

`MAD`는 중앙값 절대편차다. 평균과 표준편차보다 극단값의 영향을 덜 받는다.

초기 비교 집단 후보:

- 동일 종목 최근 20거래일
- 동일 시간대
- 동일 구간 길이
- 기업행동과 거래정지 등 비정상일 제외

데이터가 충분하지 않은 신규 종목은 유동성·시가총액 그룹 분포를 임시 사용하고 Flow Confidence를 낮춘다.

### 점수 압축

극단값이 점수를 지배하지 않도록 다음과 같이 `-100~+100`으로 압축할 수 있다.

```text
Score(z) = 100 × tanh(z / k)
```

초기값 `k=2`는 검증 필요다.

## 9. Actor Flow Direction Score

각 투자 주체의 현재 수급 방향을 나타내는 내부 기본 점수다.

### 입력값

```text
Z5_a   = RobustZ(FlowRatio_a(t,5))
Z15_a  = RobustZ(FlowRatio_a(t,15))
ZCum_a = RobustZ(CumFlowRatio_a(t))
```

### 초기 계산식

```text
RawDirection_a
= 0.45 × Z5_a
+ 0.35 × Z15_a
+ 0.20 × ZCum_a
```

```text
DirectionScore_a = 100 × tanh(RawDirection_a / 2)
```

초기 가중치 해석:

- 최근 5분: 현재 전환 탐지에 가장 높은 비중
- 최근 15분: 노이즈 필터와 지속성
- 당일 누적: 전체 방향 확인

이 가중치는 모든 투자 주체에 고정하지 않는다. 프로그램은 5분 비중을 높게, 갱신이 느린 주체는 15분·누적 비중을 높게 검증할 수 있다.

## 10. Flow Shift

### 정의

Flow Shift는 투자 주체의 수급 방향이 매수와 매도 사이에서 전환되거나 기존 압력이 약화·강화되는 상태를 탐지한다.

### 기본 입력

- DirectionScore
- 최근 5분·15분 Flow Ratio
- 이전 DirectionScore
- Flow Acceleration
- Flow Persistence
- 데이터 품질

### 초기 상태 구간

| DirectionScore | 기본 방향 상태 |
|---:|---|
| `+60~+100` | Strong Buy |
| `+25~+59` | Buy |
| `-24~+24` | Neutral |
| `-59~-25` | Sell |
| `-100~-60` | Strong Sell |

위 구간은 초기값이며 검증 필요다.

### 전환 상태

| 상태 | 판정 개념 |
|---|---|
| Strong Bullish Shift | 강한 매도권에서 강한 매수권으로 빠르게 전환 |
| Bullish Shift | 매도 또는 중립에서 매수권 진입 후 확인 |
| Weakening Sell | 여전히 음수지만 매도 강도가 의미 있게 감소 |
| Neutral | 방향 불명확 또는 확인 부족 |
| Weakening Buy | 여전히 양수지만 매수 강도가 의미 있게 감소 |
| Bearish Shift | 매수 또는 중립에서 매도권 진입 후 확인 |
| Strong Bearish Shift | 강한 매수권에서 강한 매도권으로 빠르게 전환 |

### Bullish Shift 초기 판정 예시

```text
이전 상태가 Sell 또는 Weakening Sell
AND DirectionScore_a >= +25
AND ΔN_a(t,5) > 0
AND 확인 구간 동안 매수권 유지
AND Q_a(t) >= 데이터 품질 기준
```

### Bearish Shift 초기 판정 예시

```text
이전 상태가 Buy 또는 Weakening Buy
AND DirectionScore_a <= -25
AND ΔN_a(t,5) < 0
AND 확인 구간 동안 매도권 유지
AND Q_a(t) >= 데이터 품질 기준
```

### 히스테리시스

점수가 경계 근처에서 반복 전환되는 문제를 막기 위해 진입 임계값과 해제 임계값을 다르게 둔다.

초기 예시:

```text
Buy 진입       +25 이상
Buy 해제       +10 미만
Sell 진입      -25 이하
Sell 해제      -10 초과
```

### 확인시간

초기 후보:

- 연속 2개 1분 계산 주기 유지
- 또는 5분봉 확정 시 유지

두 방식의 지연과 오탐률을 백테스트로 비교한다.

## 11. Flow Acceleration

### 정의

Flow Acceleration은 순매수·순매도 속도가 강화되는지 약화되는지 측정한다.

### 기본 계산

```text
Velocity_a(t) = FlowRatio_a(t,5)
```

```text
Acceleration_a(t)
= Velocity_a(t) - Velocity_a(t-5분)
```

표준화 점수:

```text
AccelerationScore_a
= 100 × tanh(RobustZ(Acceleration_a) / 2)
```

### 사용자 상태 문구

| 점수 | 문구 |
|---:|---|
| `+50 이상` | 매수 속도 빠르게 증가 |
| `+20~+49` | 매수 속도 증가 |
| `-19~+19` | 속도 변화 제한적 |
| `-49~-20` | 매수 약화 또는 매도 증가 |
| `-50 이하` | 매도 속도 빠르게 증가 |

표현은 현재 방향과 함께 조합한다. 예를 들어 누적 순매수가 양수인데 Acceleration이 음수이면 `프로그램 매수 유지·속도 둔화`로 표시한다.

## 12. Flow Persistence

### 정의

현재 수급 방향이 얼마나 오래, 얼마나 일관되게 유지되었는지를 측정한다.

### 기본 요소

```text
Duration = 현재 방향 상태가 연속 유지된 시간
```

```text
Consistency
= 최근 n개 구간 중 현재 방향과 같은 구간 수 / n
```

```text
ReversalPenalty
= 최근 n개 구간의 방향 전환 횟수에 대한 감점
```

### 초기 계산식

```text
PersistenceScore
= 100 × (
    0.50 × DurationScore
  + 0.40 × Consistency
  + 0.10 × (1 - ReversalPenalty)
)
```

`DurationScore`는 일정 시간 이후 1에 가까워지는 포화 함수로 계산한다.

예시:

```text
Flow Persistence
매수 흐름 18분 지속
최근 15개 1분 구간 중 12개 순매수
```

장 시작 직후에는 최대 지속시간이 짧으므로 시간대별 보정을 적용한다.

## 13. Flow Sync

### 정의

Flow Sync는 외국인·기관·프로그램·개인의 현재 방향이 얼마나 일치하는지 나타낸다.

### 주체별 유효 가중치

```text
EffectiveWeight_a
= BaseWeight_a × DataQuality_a × Availability_a
```

- `BaseWeight`: 투자 주체별 기본 가중치
- `DataQuality`: 0~1 데이터 품질
- `Availability`: 사용 가능하면 1, 사용 불가능하면 0

### 방향 점수

```text
WeightedDirection
= Σ(EffectiveWeight_a × DirectionScore_a)
 / Σ(EffectiveWeight_a)
```

### 동의도

```text
Agreement
= 같은 방향에 속한 유효 가중치 합
 / 전체 유효 가중치 합
```

### 초기 Flow Sync 계산

```text
FlowSync
= clamp(
    WeightedDirection × (0.5 + 0.5 × Agreement),
    -100,
    +100
)
```

### 상태 구간 초기값

| 점수 | 상태 |
|---:|---|
| `+60~+100` | 강한 매수 동조 |
| `+25~+59` | 약한 매수 동조 |
| `-24~+24` | 방향 혼재 또는 중립 |
| `-59~-25` | 약한 매도 동조 |
| `-100~-60` | 강한 매도 동조 |

### 개인 수급 처리

개인 수급의 부호를 자동으로 반전해 사용하지 않는다. 개인 순매수는 그대로 표시하되 외국인·기관·프로그램과 반대 방향이면 `Divergent`로 표현한다.

초기 MVP에서는 다음 두 값을 함께 저장한다.

- `CoreSync`: 외국인·기관·프로그램
- `AllActorSync`: 외국인·기관·프로그램·개인

두 방식 중 사용자 이해도와 예측력에 더 유효한 표현을 검증한다.

## 14. Flow Divergence

### 정의

가격과 선택 투자 주체의 수급이 반대로 움직이는 정도를 측정한다.

### 가격 방향 점수

```text
PriceScore_h
= 100 × tanh(RobustZ(R_p(t,h)) / 2)
```

### 괴리 점수

```text
DivergenceRaw_a
= (DirectionScore_a - PriceScore_5) / 2
```

해석:

- 큰 양수: 가격은 약하지만 수급은 강함
- 큰 음수: 가격은 강하지만 수급은 약함
- 0 근처: 가격과 수급 방향이 유사

### 사용자 상태

| 가격 | 수급 | 상태 |
|---|---|---|
| 하락 | 매수 | Positive Divergence · 반등 후보 괴리 |
| 상승 | 매도 | Negative Divergence · 상승 약화 경고 |
| 상승 | 매수 | 상승 흐름 일치 |
| 하락 | 매도 | 하락 흐름 일치 |

Divergence는 반전의 충분조건이 아니다. 가격 확인과 Flow Persistence를 함께 사용한다.

---

## 15. Flow Confidence

### 정의

Flow Confidence는 예상 상승 확률이 아니라 현재 데이터와 신호를 판단 자료로 사용할 수 있는 신뢰 수준이다.

### 구성 요소

| 구성 | 초기 비중 | 내용 |
|---|---:|---|
| Data Quality | 30% | 누락·지연·확정/추정·정정 상태 |
| Liquidity | 10% | 거래대금·체결 안정성 |
| Persistence | 15% | 방향 지속성과 전환 반복 여부 |
| Timeframe Alignment | 15% | 5분·15분·30분 방향 일치 |
| Price/Volume Confirmation | 15% | 가격 반전·거래량 확인 |
| Historical Calibration | 15% | 과거 동일 버전 신호의 표본과 보정 |

### 초기 계산식

```text
FlowConfidence
= 0.30 × DataQuality
+ 0.10 × Liquidity
+ 0.15 × Persistence
+ 0.15 × TimeframeAlignment
+ 0.15 × PriceVolumeConfirmation
+ 0.15 × HistoricalCalibration
```

모든 구성요소는 `0~100`으로 정규화한다.

### 데이터 하드 캡

데이터 품질이 낮은데 다른 요소 때문에 Confidence가 높아지지 않도록 상한을 둔다.

초기 예시:

```text
확정 데이터 누락         최대 49점
허용 지연 초과           최대 39점
핵심 주체 데이터 없음     신호 계산 중단
기준 시각 불명           신호 계산 중단
```

정확한 지연 허용치는 데이터 공급 주기별로 설정한다.

### 상태 문구 초기값

| 점수 | 상태 |
|---:|---|
| `80~100` | 높음 |
| `65~79` | 보통 이상 |
| `50~64` | 관찰 필요 |
| `0~49` | 낮음·신호 확정 불가 |

`78/100`은 상승 확률 78%가 아니다. UI에 이 설명을 제공한다.

## 16. Data Quality Score

Flow Confidence의 핵심 하위 점수다.

### 초기 구성

```text
DataQuality
= Completeness 35%
+ Freshness 30%
+ TimestampIntegrity 15%
+ ConfirmedVsEstimated 10%
+ CorrectionStability 10%
```

### 점검 항목

- 예상 데이터 포인트 수 대비 수신 비율
- 공급사 기준 시각과 서버 수신 시각 차이
- 역순·중복 이벤트 여부
- 장중 추정값 여부
- 최근 정정 횟수

데이터 품질 문제는 점수만 낮추지 않고 사용자에게 원인을 표시한다.

## 17. Timeframe Alignment

### 정의

5분·15분·30분 가격과 수급 방향이 서로 일치하는 정도다.

초기 예시:

```text
5분 수급 방향 일치        40점
15분 수급 방향 일치       35점
30분 또는 누적 방향 일치   25점
```

최근 5분은 매수인데 15분·30분이 강한 매도이면 단기 반전 시도 또는 노이즈로 표시한다.

## 18. Price/Volume Confirmation

### 진입 확인 요소

- 5분 Envelope 하단 재진입
- 직전 5분봉 고가 돌파
- 직전 저점 또는 당일 저점 방어
- 거래량 회복
- VWAP 회복

### 청산 확인 요소

- 5분 Envelope 상단 재진입
- 직전 고점 돌파 실패
- 직전 5분봉 저점 이탈
- 거래량을 동반한 반락
- VWAP 하향 이탈

초기에는 각 조건을 Boolean으로 저장하고, 최종 조합은 백테스트로 결정한다.

## 19. Flow Impact

### 정의

Flow Impact는 동일한 순매수 금액이 종목 가격에 미치는 상대적 영향을 추정한다.

### 초기 후보 입력

- 거래대금 대비 순매수 비율
- 시가총액 또는 유통시가총액
- 호가 스프레드
- 체결 강도와 유동성
- 순매수 변화 이후 가격 반응

초기 후보식:

```text
ImpactProxy_a
= FlowRatio_a(t,5)
 / max(최근 변동성, ε)
```

Flow Impact는 데이터 요구량과 시장 미시구조 검증이 필요하므로 P1 사용자 노출을 원칙으로 한다. MVP에서는 내부 실험 지표로 저장할 수 있다.

## 20. Signal Phase

모든 Actor Playbook은 공통 상태 머신을 사용한다.

```text
CANDIDATE
→ WAITING_CONFIRMATION
→ ENTRY_CONFIRMED
→ FLOW_HOLDING
→ FLOW_WEAKENING
→ EXIT_CONFIRMED
→ CLOSED
```

어느 단계에서든 무효 조건이 발생하면 다음으로 전환한다.

```text
INVALIDATED
```

### 상태 정의

| 상태 | 의미 |
|---|---|
| CANDIDATE | 기본 가격·수급 조건 충족 |
| WAITING_CONFIRMATION | 수급 조건 충족, 가격 반전 미확인 |
| ENTRY_CONFIRMED | 사전 정의한 가격·수급 확인 완료 |
| FLOW_HOLDING | 선택 주체 매수 흐름 유지 |
| FLOW_WEAKENING | 매수 가속도 둔화 또는 정체 |
| EXIT_CONFIRMED | Rally Exit 또는 위험 청산 조건 충족 |
| INVALIDATED | 진입 가설 무효 |
| CLOSED | 사용자 기록상 당일청산 완료 |

상태 전환마다 시각·원인·지표 스냅샷을 저장한다.

## 21. Risk/Invalidation

Risk/Invalidation은 단일 점수가 아니라 현재 신호를 무효화하는 조건 집합이다.

### 가격 무효

- 당일 저점 이탈
- 신호 기준 저점 이탈
- 사용자 최대 손실 도달
- 급격한 변동성 확대

### 수급 무효

- 선택 주체 Bearish Shift
- 최근 5분·15분 순매도 전환
- Flow Persistence 붕괴
- 강한 Bearish Sync

### 데이터 무효

- 허용 지연 초과
- 핵심 구간 누락
- 공급사 정정 진행
- 기준 시각 불명

### 시간 무효

- 진입 확인 없이 최대 대기시간 초과
- 진입 후 반등 없이 최대 보유시간 초과
- 장 마감 전 청산 시각 도달

하드 무효와 경고 무효를 구분한다.

- Hard Invalidation: 신호 종료 및 추가 진입 잠금
- Soft Warning: Confidence 감점 및 확인 필요

## 22. Envelope 계산

원본 조건식의 기본 설정을 초기 검증값으로 사용한다.

### 중심선

```text
Middle = 이동평균(Close, 20)
```

### 상단·하단

```text
Upper = Middle × (1 + p)
Lower = Middle × (1 - p)
```

초기 설정:

| 시간봉 | 기간 | 편차 |
|---|---:|---:|
| 30분봉 | 20 | 2.0% |
| 5분봉 | 20 | 0.5% |

이 설정은 기존 조건식에서 가져온 검증 출발점이며 최적값으로 확정된 것이 아니다.

### 상태 구분

- Lower Break: 종가가 하단 이하
- Lower Re-entry: 이전 종가가 하단 이하이고 현재 종가가 하단 위
- Upper Break: 종가가 상단 이상
- Upper Re-entry: 이전 종가가 상단 이상이고 현재 종가가 상단 아래

## 23. Program Dip Reversal

### 전략 정의

가격은 단기 과매도 상태지만 프로그램 누적 수급은 플러스이고 최근 프로그램 매수가 유지·강화되며 가격 반전 조건이 확인될 때 발생하는 데이트레이딩 관찰 신호다.

### 1단계: 하드 필터

초기 후보 조건:

```text
당일 등락률 < 0
AND 프로그램 누적 순매수 > 0
AND 프로그램 누적 순매수 >= 절대금액 최소값
AND 프로그램/거래대금 비율 >= 최소 비율
AND 30분 Envelope Lower Break
AND 최소 거래대금 충족
AND 거래 가능 종목
AND Data Quality 기준 충족
```

기존 조건식의 `프로그램 순매수 5억원 이상`은 초기 절대금액 후보값으로 보존하되 단독 조건으로 사용하지 않는다.

### 2단계: 수급 확인

```text
최근 5분 프로그램 순매수 > 0
AND 최근 15분 프로그램 흐름이 강한 매도가 아님
AND Flow Shift가 Bullish 또는 Buy/Holding
AND Flow Acceleration이 허용 기준 이상
AND Flow Persistence가 최소 기준 이상
```

### 3단계: 가격 확인

초기 확인 후보 중 최소 개수 충족 방식으로 검증한다.

- 5분 Envelope Lower Re-entry
- 직전 5분봉 고가 돌파
- 당일 또는 직전 저점 방어
- 거래량 회복
- VWAP 회복

### 4단계: Confidence 게이트

초기 UI 정책 후보:

| Confidence | 처리 |
|---:|---|
| `80 이상` | 높은 신뢰 관찰 신호 |
| `65~79` | 일반 관찰 신호 |
| `50~64` | 후보 목록만 표시, 강한 알림 제한 |
| `50 미만` | 신호 확정 금지 |

구간은 검증 필요다.

### Program Dip Score

하드 필터를 통과한 후보의 정렬용 점수다.

초기 구조:

```text
ProgramDipScore
= 0.25 × ProgramDirection
+ 0.15 × FlowAcceleration
+ 0.15 × FlowPersistence
+ 0.15 × PositiveDivergence
+ 0.15 × PriceConfirmation
+ 0.15 × FlowConfidence
```

하드 무효 조건은 점수보다 우선한다.

## 24. 최대 4~5회 조건부 분할진입 모델

FlowPulse는 주문을 실행하지 않으며 사용자가 실제 주문 결과를 기록한다.

### 진입 단계 예시

| 차수 | 조건 후보 | 역할 |
|---|---|---|
| 1차 | 수급 후보 + 초기 반전 징후 | 최소 탐색 비중 |
| 2차 | Lower Re-entry | 가격 반전 확인 |
| 3차 | 직전 5분봉 고가 돌파 | 모멘텀 확인 |
| 4차 | 프로그램 매수 지속·Confidence 유지 | 수급 지속 확인 |
| 5차 | VWAP 회복 또는 추가 가격 확인 | 최종 확인 |

### 금지 조건

다음 중 하나라도 발생하면 다음 차수를 활성화하지 않는다.

- 가격이 더 하락했다는 이유만 존재
- 프로그램 최근 5분 순매도
- Bearish Shift
- 당일 저점 이탈
- Flow Confidence 하한 미달
- 데이터 지연·누락
- 최대 손실 도달

차수별 비중은 제품 기본값으로 확정하지 않고 백테스트와 사용자 위험 설정으로 분리한다.

## 25. Program Rally Exit

### 전략 정의

보유 종목이 단기 과매수 또는 목표수익 구간에 도달하고 프로그램 매수세가 둔화하거나 순매도로 전환될 때 수익을 보호하는 동적 청산 신호다.

### 1단계: 적용 조건

```text
사용자 기록상 보유 수량 > 0
AND 당일청산 Playbook 활성
```

### 2단계: 과매수 후보

- 5분 Envelope Upper Break 또는 Upper Re-entry
- 30분 Envelope 상단 접근·돌파
- VWAP 대비 과도한 상승
- 직전 저점 대비 단기 급등
- 고정 목표수익 1~3% 구간 접근

### 3단계: 프로그램 약화·매도 확인

- 프로그램 누적 순매수 증가 속도 둔화
- 최근 5분 프로그램 순매수 0 근처
- 최근 5분 프로그램 순매도
- 프로그램 Bearish Shift
- Flow Acceleration 음수 확대
- Flow Persistence가 매도 방향으로 전환

### 4단계: 가격 반락 확인

- 5분 Envelope Upper Re-entry
- 직전 고점 돌파 실패
- 직전 5분봉 저점 이탈
- VWAP 하향 이탈
- 거래량을 동반한 반락

### Exit Severity

| 단계 | 조건 개념 | 상태 문구 |
|---|---|---|
| 1 | 과매수 + 매수 가속도 둔화 | 수익 보호 준비 |
| 2 | 최근 5분 매도 전환 | 분할청산 조건 |
| 3 | Bearish Shift + 가격 반락 | 강한 청산 조건 |
| 4 | 매도 지속 또는 하드 위험 | 전량청산 조건 |

FlowPulse는 상태를 제공하고 주문은 사용자가 직접 실행한다.

---

## 26. 고정 익절과 동적 익절 결합

검증할 청산 방식은 다음 세 가지다.

### A. 고정 익절

```text
+1%, +2%, +3% 구간 분할청산
```

### B. 동적 익절

```text
과매수 + 프로그램 매수 둔화·Bearish Shift
```

### C. 결합 익절

```text
최소 목표수익에서 일부 수익 보호
→ 잔여 수량은 Program Rally Exit 추적
→ 마감 시각 전 전량청산
```

세 방식의 결과를 동일 데이터와 비용 가정으로 비교한다. 승률뿐 아니라 평균손익·손익비·MFE·MAE·보유시간을 함께 평가한다.

## 27. 시간청산

데이트레이딩 Playbook은 다음 날 보유하지 않는다.

### 필수 시간 규칙

- 장 막판 신규 신호 제한
- 마감 전 사용자 알림
- 지정 시각까지 잔여 수량 전량청산 기록
- 신호 발생 후 최대 대기시간
- 진입 후 최대 보유시간

기본 시각은 거래소 운영시간, 증권사 주문 가능시간, 실제 체결 위험을 검토한 뒤 확정한다.

다음 날 보유한 기록은 전략 규칙 이탈로 표시하고 당일청산 성과 표본과 구분한다.

## 28. 투자 주체별 적용

### Program

- 장중 변화 탐지에 가장 먼저 적용
- 최근 5분·15분 변화량과 누적값 결합
- Program Dip Reversal과 Rally Exit의 초기 대표 주체

### Foreign

- Foreign Dip Reversal / Rally Exit
- 데이터 갱신 주기와 추정 여부를 Confidence에 반영
- 프로그램과 동시 전환 시 Flow Sync 강화 여부 검증

### Institution

- Institution Dip Reversal / Rally Exit
- 기관 합계와 세부 유형 제공 가능 범위를 분리
- 프로그램 수급과 중복 관계를 검토

### Retail

- Retail Dip Reversal / Rally Exit
- 개인 순매수를 무조건 긍정 신호로 해석하지 않음
- 외국인·기관·프로그램의 반대 흐름과 함께 평가

각 주체의 데이터 범위가 다르면 동일한 Confidence 구성과 임계값을 강제하지 않는다.

## 29. 복합 Actor Playbook

### Multi-Actor Bullish Shift

```text
외국인 Bullish Shift
AND 기관 또는 프로그램 Bullish/Buy
AND CoreSync >= 매수 동조 기준
AND 가격 확인
AND Confidence 기준 충족
```

### Multi-Actor Bearish Shift

```text
외국인 Bearish Shift
AND 기관 또는 프로그램 Bearish/Sell
AND CoreSync <= 매도 동조 기준
AND 가격 약화 확인
AND Confidence 기준 충족
```

복합 신호는 단일 주체보다 항상 우수하다고 가정하지 않고 별도 표본으로 검증한다.

- 최근 5분 순매수 변화량
- 필요 시 거래대금 대비 비율

### 표시 예시

```text
Flow Shift          프로그램 매수 유지
Flow Sync           +32 · 약한 매수 동조
Flow Confidence     78/100 · 높음
Flow Divergence     가격↓ / 프로그램↑
Flow Persistence    매수 흐름 18분 지속
Flow Acceleration   매수 속도 증가
```

점수와 함께 사람이 이해할 수 있는 상태 문구를 제공한다.

## 32. 지표 버전 관리

계산식이나 임계값이 바뀌면 새 버전을 생성한다.

예시:

```text
flow_shift_v1.0.0
flow_sync_v1.0.0
flow_confidence_v1.0.0
program_dip_reversal_v1.0.0
program_rally_exit_v1.0.0
```

### 버전 규칙

- Major: 계산 의미 또는 입력 구조 변경
- Minor: 가중치·임계값·상태 구간 변경
- Patch: 계산 오류 수정, 의미 유지

다른 Major 버전의 사후 결과를 동일 전략처럼 단순 합산하지 않는다.

## 33. 백테스트 기본 원칙

### 데이터 원칙

- 당시 시점에 이용 가능했던 데이터만 사용
- 정정된 최종값을 장중 실시간 값처럼 사용하지 않음
- 상장폐지·거래정지 종목 포함 여부 명시
- 액면분할·배당락·권리락 등 기업행동 조정
- 휴장·반일장·동시호가 구간 처리

### 비용 원칙

- 매매 수수료
- 세금
- 호가 스프레드
- 슬리피지
- 체결 가능 수량

### 검증 분리

- 학습·탐색 구간
- 검증 구간
- 최종 홀드아웃 구간
- 가능하면 Walk-forward 검증

임계값을 전체 데이터 결과에 맞춰 반복 조정한 뒤 같은 데이터에서 성과를 보고하지 않는다.

## 35. Confidence 보정 검증

Flow Confidence가 실제로 의미 있으려면 높은 점수 구간이 낮은 점수 구간보다 데이터 완전성 및 신호 일관성이 높아야 한다.

검증 방법:

1. Confidence 구간별 표본 분리
2. 데이터 오류율 비교
3. 신호 무효율 비교
4. 가격 확인 성공률 비교
5. 사후 성과 분포 비교
6. 필요 시 등위 보정 또는 Isotonic Calibration 검토

성과와 Confidence의 관계가 약하면 `신뢰도` 표현과 구성식을 재검토한다. 예상 수익 확률로 표시하지 않는다.

## 36. 과최적화 방지

- 종목별로 지나치게 다른 임계값을 사용하지 않는다.
- 거래일마다 임계값을 임의 조정하지 않는다.
- 표본 수가 작은 조건을 대표 신호로 승격하지 않는다.
- 실패 구간을 제외하여 결과를 좋게 만들지 않는다.
- 수많은 조건 조합 중 최고 결과 하나만 보고하지 않는다.
- 시장 국면 변화에 대한 민감도를 별도로 공개한다.

복잡한 모델이 단순 기준보다 명확히 개선되지 않으면 단순 기준을 사용한다.

## 40. 확정 사항

다음은 지표 설계에서 변경하지 않는 제품 요구사항이다.

1. Flow Shift는 매수·매도 양방향이다.
2. Flow Sync는 매수·매도 동조와 방향 충돌을 표현한다.
3. Flow Confidence는 모든 핵심 신호에 포함한다.
4. Flow Divergence·Persistence·Acceleration을 핵심 카드에 포함한다.
5. 프로그램·외국인·기관·개인에 공통 Actor 엔진을 적용한다.
6. Program Dip Reversal은 가격 과매도와 프로그램 매수를 함께 본다.
7. Program Rally Exit은 가격 과매수와 프로그램 매도 유입을 함께 본다.
8. 분할진입은 가격 하락이 아니라 추가 확인 조건으로 활성화한다.
9. 고정 1~3% 익절과 동적 익절을 함께 검증한다.
10. 데이트레이딩 Playbook은 당일청산하며 다음 날 보유하지 않는다.
11. 모든 신호와 지표는 사후검증한다.
